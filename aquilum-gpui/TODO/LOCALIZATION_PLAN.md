# План внедрения масштабируемой локализации (i18n) в `aquilum-gpui`

Документ описывает архитектуру и пошаговый план внедрения системы мультиязычности (с поддержкой 20+ языков) в проект **`aquilum-gpui`** (`vibecodium`).

---

## 1. Анализ текущего состояния проекта

| Компонент | Текущее состояние | Что требуется сделать |
| :--- | :--- | :--- |
| **`SettingsManager` / `UiSettings`** | Поле `pub language: String` уже объявлено в `src/settings.rs`. | Добавить валидацию кода языка, автоопределение системной локали при первом запуске и уведомление UI об изменениях. |
| **UI переключения языка** | В `src/views/settings_view.rs` есть примитивный переключатель `ru` ↔ `en`. | Заменить на полноценный выпадающий список (Dropdown / Select modal) с поддержкой 20+ языков и поиском. |
| **Модуль i18n** | Полностью отсутствует в проекте. | Создать `src/i18n.rs` с ленивой загрузкой, fallback-механизмом и форматированием параметров. |
| **Строки интерфейса** | 100% строк захардкожены на русском языке (вкладки настроек, контекстные меню, диалоги, плейсхолдеры). | Провести поэтапную экстракцию всех строк в JSON-ресурсы. |

## 2. Архитектура решения для 20+ языков

### Принципы архитектуры

1. **Zero-dependency deployment (Вкомпилированные ресурсы)**:
   Все 20+ языковых файлов вшиваются прямо в бинарный файл во время сборки (`include_str!` или `rust-embed`). Это гарантирует, что программа будет работать автономно (один `.exe` файл), файлы переводов не будут случайно удалены или заблокированы антивирусом. Общий объём 20 файлов не превысит ~200 КБ (< 1% размера бинарника GPUI).

2. **Изолированные файлы ресурсов**:
   Каждый язык хранится в отдельном файле `locales/{code}.json`. Это исключает конфликты слияния в Git и позволяет передавать файлы внешним переводчикам без необходимости работы с кодом на Rust.

3. **Строгая валидация в тестах (`cargo test`)**:
   Автоматический тест сверяет структуру всех языковых файлов с эталонным `en.json`. Если в каком-то языке отсутствует ключ, тест выдаст ошибку с указанием недостающих ключей.

4. **Многоуровневый Fallback**:
   Цепочка поиска: `Запрошенный язык` $\rightarrow$ `en` (английский эталон) $\rightarrow$ `Имя ключа`.

5. **(Опционально) Внешние переопределения**:
   Возможность подгружать пользовательские переводы из `%APPDATA%/.vibecodium/locales/` поверх встроенных для пользовательской кастомизации.

## 3. Поэтапный план реализации

### Этап 1: Базовая инфраструктура и модуль `i18n`

- [ ] **1.1. Создание каталога и эталонных файлов**:
  - Создать директорию `locales/` в корне проекта `aquilum-gpui`.
  - Создать `locales/en.json` и `locales/ru.json`.
  - Организовать ключи по пространствам имён (namespaces):
    ```json
    {
      "settings": {
        "tabs": {
          "ui": "Interface",
          "editor": "Editor",
          "search": "Search"
        },
        "ui": {
          "language": "Interface Language",
          "theme": "Theme"
        }
      },
      "sidebar": {
        "new_file": "New Note",
        "delete": "Delete"
      }
    }
    ```

- [ ] **1.2. Создание реестра языков (`src/i18n.rs`)**:
  - Описать метаданные языка:
    ```rust
    #[derive(Debug, Clone, Copy, PartialEq, Eq)]
    pub struct LocaleInfo {
        pub code: &'static str,         // "ru", "en", "de"
        pub native_name: &'static str,  // "Русский", "English", "Deutsch"
        pub english_name: &'static str, // "Russian", "English", "German"
    }
    ```
  - Зарегистрировать массив поддерживаемых языков `SUPPORTED_LOCALES`.

- [ ] **1.3. Реализация движка переводов**:
  - Вкомпилировать JSON-файлы через макрос сопоставления:
    ```rust
    macro_rules! register_locales {
        ($($code:expr => $path:expr),* $(,)?) => { ... };
    }
    ```
  - Использовать `once_cell::sync::Lazy` / `std::sync::OnceLock` для ленивого парсинга JSON в память.
  - Реализовать API получения переводов:
    ```rust
    pub fn t(key: &str, lang: &str) -> String;
    pub fn t_args(key: &str, lang: &str, args: &[(&str, &str)]) -> String;
    ```

- [ ] **1.4. Интеграция с системным языком**:
  - Если в `UiSettings.language` пусто, определять системный язык ОС при первом запуске (с откатом на `en`).

- [ ] **1.5. Написание тестов целостности (`tests/i18n_parity_test.rs`)**:
  - Проверка валидности синтаксиса всех JSON-файлов в папке `locales/`.
  - Проверка наличия всех ключей из `en.json` во всех остальных локалях.

## 4. Важные нюансы реализации в GPUI

1. **Динамическая длина текста**:
   Слова в немецком, французском и польском языках длиннее английских на 20–40%. В кнопках, плашках и колонках настроек избегать жестко фиксированной ширины (`w(px(120.0))`). Использовать `min_w`, `flex_1` или автоматический расчет размеров.

2. **Плейсхолдеры в `InputState`**:
   В GPUI плейсхолдеры часто задаются при инициализации инпута в `new()`. При переключении языка необходимо либо динамически обновлять плейсхолдеры (`set_placeholder`), либо пересоздавать компонент ввода.

3. **Форматирование чисел и дат**:
   Разделители тысяч, форматирование дат и времени должны учитывать выбранную локаль.
