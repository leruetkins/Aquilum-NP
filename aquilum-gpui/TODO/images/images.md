# Задание: вставка и хранение изображений

## Цель

Вставлять изображения в заметки (в первую очередь скриншоты из буфера обмена) и хранить так, чтобы папку с заметками можно было копировать и переносить без битых ссылок.

Обрезка, сжатие и аннотации необязательны. Пользователь сам решает, нужно ли ему редактировать картинку: по умолчанию изображение вставляется как есть, а редактирование запускается кнопками в самом редакторе (см. «Редактирование изображения»).

## Модель хранения

- Вложения лежат в папке `attachments/` рядом с заметкой (имя папки настраивается, по умолчанию `attachments`).
- В заметке хранится только имя файла: `![[2026-10-31-1515-k3x9.png]]`. Путь не пишется.
- Имя файла: дата и время + короткий случайный суффикс. Уникально на всё хранилище. Не чистый хэш содержимого, чтобы копия получала новое имя.
- Один файл принадлежит одной заметке.
- Папку `attachments` скрывать только в проводнике приложения (настройка «Показывать папки вложений», по умолчанию выключена). На диске она обычная, не скрытая. Из списка заметок, графа и поиска по тексту исключать.
- Если у изображения есть обрезка, аннотации, подпись или своё скругление углов, рядом лежит файл `имя.edit.json` (см. «Хранение правок»). Пара `имя.png` + `имя.edit.json` это один вложенный файл: она копируется, переносится, удаляется, уходит в корзину и экспортируется вместе, а при копировании получает новое имя.

## Поиск файла по ссылке (`resolve_attachment(note_path, name)`)

Одна функция, вызывается везде (отрисовка, экспорт, проверка битых ссылок). Порядок:

1. `attachments/` рядом с заметкой.
2. Корзина вложений (`attachments/.trash/` в корне хранилища): показать, вернуть рядом с заметкой при сохранении или отмене.
3. Общая `attachments/` в корне хранилища: **копировать** рядом с заметкой.
4. Словарь «имя файла → пути» по хранилищу (строится в памяти при открытии, обновляется наблюдателем за файлами): **копировать** рядом с заметкой.
5. Не найдено: показать как битую ссылку, ничего не менять.

Правило: переносить можно только из корзины. Из общей папки и чужих заметок только копировать.

Копию на диск писать при сохранении заметки, а не при отрисовке. Показывать картинку можно сразу. Вместе с файлом всегда находить и копировать его `.edit.json`, если он есть.

## Операции

| Действие | Поведение |
|---|---|
| Вставка из буфера (скриншот) | Сразу записать файл как есть в `attachments/` рядом с заметкой и вставить ссылку. Никаких диалогов. Редактирование по желанию кнопками на картинке (по настройке можно открывать редактор сразу при вставке, по умолчанию выключено) |
| Copy + Paste ссылки в другую заметку | Новая копия файла (и `.edit.json`) с новым именем в `attachments/` новой заметки, ссылка в вставляемом тексте переписывается |
| Cut + Paste в другую заметку | Файл (и `.edit.json`) переносится в `attachments/` новой заметки, имя сохраняется. Если на имя есть ссылки из других заметок, копировать вместо переноса |
| Вставка в ту же заметку | Решать по смыслу: новая копия или та же ссылка (по умолчанию новая копия) |
| Удаление ссылки | Файл не удалять сразу. Удалять при сохранении, если в сохранённой версии ссылки нет. Удаление = перенос в корзину |
| Удаление заметки | Вложения уходят в корзину |
| Перенос заметки через приложение | Вложения переносятся в `attachments/` новой папки |
| Вставка из внешнего приложения | Текст как текст. Изображения и файлы-изображения импортируются по правилам раздела «Импорт изображений извне» |

Корзина: очистка файлов старше 30 дней (настраивается) и кнопка «Очистить».

## Импорт изображений извне (буфер, проводник, перетаскивание)

Правило одно: **вставка есть только вставка**. Изображение сразу появляется в заметке, редактирование не запускается, модальных окон нет. Ошибки показываются ненавязчивыми уведомлениями (toast).

### Источники

| Источник | Что приходит | Что делаем |
|---|---|---|
| Перетаскивание файлов из проводника | Список путей | Копируем в `attachments/` заметки, оригинал не трогаем. Вставляем в то место, где отпущен файл (позиция курсора под мышью). При перетаскивании подсвечиваем место вставки |
| Ctrl+V после Ctrl+C файла в проводнике | Список путей в буфере | То же самое, вставка в позицию курсора |
| Ctrl+V изображения из Paint, браузера, редакторов, скриншот | Растровые данные | Кодируем в PNG, сохраняем с новым именем, вставляем ссылку. Картинку из браузера не скачиваем по адресу, берём только растр из буфера |
| Кнопка/команда «Вставить изображение…» | Список путей из выбора файла | То же самое |

Если файлов несколько, вставляем их по очереди, каждую ссылку с новой строки. Весь импорт одной операции (файлы и ссылки) отменяется одним Undo.

### Единый механизм

Все источники проходят через одну функцию, отличаются только способом получения данных:

```rust
enum ImageImportSource {
    ClipboardImage(RawImage),
    ClipboardFiles(Vec<PathBuf>),
    DragAndDrop(Vec<PathBuf>),
    FilePicker(Vec<PathBuf>),
}

async fn import_images(note: &NotePath, source: ImageImportSource)
    -> Result<Vec<ImportedImage>, ImportError>;
```

Она получает данные, проверяет формат, генерирует имя, копирует в `attachments/` и возвращает имена. Вставку ссылки в текст делает редактор. Работает в фоне, на месте вставки показывается заглушка до готовности.

### Правила

- **Имя.** Всегда новое по общей схеме (`дата-время-случайный суффикс`), как для скриншота. Нумерация `screenshot_2.png` не используется: она ломает поиск по одному имени между заметками. Исходное имя файла можно сохранить в `.edit.json` как `source_name` (для подсказки, не для ссылки).
- **Формат.** Файлы из проводника копируются байт в байт, без перекодирования (JPEG остаётся JPEG, GIF остаётся GIF). Растр из буфера сохраняется как PNG.
- **Проверка.** Перед копированием проверяем, что файл читается как изображение (заголовок/декодирование). Расширению не верим.
- **EXIF-поворот.** Для JPEG учитывать ориентацию при показе и обработке, иначе фото с телефона окажутся повёрнутыми.
- **Большой файл.** Если больше порога (настраивается), вставляем сразу, а в toast даём кнопку «Сжать». Окно не показываем.
- **Отличать свои вложения.** Буфер, в котором лежит ссылка на вложение нашего приложения, обрабатывается по правилам Copy/Cut из таблицы «Операции», а не как внешнее изображение.
- **Не изображение.** Остальные файлы при перетаскивании игнорируем с уведомлением (PDF и прочее решается отдельно).

### Ошибки

| Ситуация | Поведение |
|---|---|
| Неподдерживаемый формат | Toast с ошибкой, остальные файлы вставляются |
| Повреждённый файл | Toast с ошибкой |
| Нет доступа к файлу | Toast с ошибкой |
| Слишком большой файл | Вставка и toast с кнопкой «Сжать» |
| Нет места/ошибка записи | Toast, ссылка не вставляется |

### Платформа

Перетаскивание файлов, список файлов в буфере и растровые данные в буфере проверить в используемой версии GPUI на Windows и Linux (X11 и Wayland). Недостающее закрыть адаптерами (ограничение 5). Результат проверки записать в «Проверить перед реализацией».

## Редактирование изображения (по желанию пользователя)

Ничего не применяется автоматически. Каждое действие пользователь запускает сам.

### Кнопки

- При наведении на картинку в заметке или по клику появляется панель кнопок: **Обрезать**, **Размер**, **Скругление**, **Сжать**, **Аннотации**, **Подпись**, **Удалить** (и позже «Сохранить как…», «Копировать»).
- То же доступно из контекстного меню (ПКМ по картинке) и командной палитры.
- Вставка без редактирования остаётся основным сценарием. Настройка «Открывать редактор сразу после вставки» (по умолчанию выключена) нужна тем, кто обрезает каждый скриншот.
- Редактировать можно и уже вставленные ранее картинки, не только свежие.
- Если у картинки есть обрезка, не применённая окончательно, в панели появляется кнопка **«Показать оригинал»** (см. «Показ оригинала и правка рамки»), а на самой картинке небольшой значок «обрезано», чтобы было видно, что в файле есть скрытая часть.

Правила для GPUI:
- Единая система позиционирования: popover привязан к кнопке или объекту, контекстное меню у курсора, модальное окно по центру окна приложения, inline-элементы в потоке документа. Не делать каждое меню отдельным окном ОС.
- Одновременно открыт только один popover. Открытие другого закрывает предыдущий.
- Открытие popover или меню не сбрасывает режимы «Обрезать» и «Аннотации». Esc закрывает самый верхний слой: popover, затем режим.
- Всё управляется с клавиатуры, модальное окно возвращает фокус в редактор.

   * Список слоёв фигур: `List`, `ListItem` (`crates/component/src/list/`).
   * Ручки изменения размеров и кадрирования: `crates/component/src/resizable.rs`.

### Хранение правок (`имя.edit.json`)

- Файл `имя.png` остаётся **оригиналом**: пока пользователь не применил обрезку окончательно, из него ничего не удаляется.
- В `имя.edit.json` лежат: рамка обрезки `crop {x, y, w, h}` в пикселях оригинала и аннотации (см. ниже), тоже в координатах оригинала. Поэтому при сдвиге границ обрезки аннотации не «уезжают». Там же лежат подпись `caption` (см. «Подпись к изображению») и своё скругление `corner_radius` (см. «Скругление углов»).
- Если нет ни обрезки, ни аннотаций, ни подписи, ни своего скругления, файл не создавать (и удалить, если стал пустым).
- Показ в заметке: взять область `crop` из оригинала, масштабировать до отображаемого размера, нарисовать аннотации поверх с отсечением по рамке.
- Предупреждение в интерфейсе: «Обрезанные части остаются в файле, пока не нажато “Применить обрезку”» (важно, если на скриншоте были скрытые данные).

### Обрезка (кнопка «Обрезать»), недеструктивная

Открывает редактор обрезки. Оригинал не меняется. Рамку можно открыть и поправить в любой момент позже: границы двигаются, пока обрезка не применена окончательно.

Управление рамкой:

1. Ручки по углам и сторонам, остальное затемнено. Рамку можно перетаскивать целиком.
2. Соотношение сторон: список «Свободно», «Как у оригинала», `1:1`, `4:3`, `3:2`, `16:9`, `10×15`, `2×3`, `4×3` и своё значение (`W:H`). Кнопка «⇄» меняет альбомную ориентацию на портретную. Выбранное соотношение блокирует пропорции рамки при перетаскивании.
3. Удержание **Shift** при перетаскивании временно переключает блокировку: если пропорции заданы, Shift отпускает их, если рамка свободная, Shift фиксирует текущие.
4. Числовые поля: X, Y, ширина, высота в пикселях оригинала.
   - Если пропорции заданы и введена только ширина, высота подстраивается автоматически. Если введена только высота, подстраивается ширина.
   - Если пропорции свободные, поля независимы.
5. Рамка не выходит за пределы оригинала, минимальный размер ограничен.
6. Кнопки: **«Готово»** (сохранить рамку в `.edit.json`, оригинал цел), **«Отмена»** (Esc), **«Сбросить обрезку»**. Enter = «Готово».
7. Отдельная кнопка **«Применить обрезку окончательно»** (в редакторе обрезки и в панели картинки):
   - показывает подтверждение: «Части вне рамки будут удалены из файла. Это нельзя отменить»;
   - после подтверждения вырезать область из оригинала (`image::crop_imm`), записать в тот же файл (имя и ссылка не меняются), сдвинуть координаты аннотаций на `-x, -y` (фигуры целиком вне кадра удалить), удалить `crop` из `.edit.json`;
   - выполнять в фоне, при ошибке оригинал не трогать.

### Показ оригинала и правка рамки

Пока обрезка существует только как рамка в `.edit.json` (не применена окончательно), в заметке видна только обрезанная часть. Чтобы подвинуть границы, нужен показ полного оригинала.

1. Кнопка **«Показать оригинал»** в панели картинки (и пункт контекстного меню, двойной клик по картинке). Работает как переключатель, подпись меняется на «Скрыть оригинал».
2. После нажатия картинка прямо в заметке разворачивается до полного оригинала. Часть вне рамки затемнена, рамка обрезки с ручками видна и редактируется на месте (те же правила: соотношения сторон, Shift, числовые поля, перетаскивание рамки целиком). Отдельное окно открывать не нужно.
3. Аннотации показываются на всём оригинале, в том числе вне рамки (приглушённо).
4. Кнопки в этом режиме: **«Готово»** (сохранить новую рамку, вернуться к обрезанному виду), **«Отмена»** или Esc (вернуть прежнюю рамку), **«Сбросить обрезку»**, **«Применить обрезку окончательно»**. Клик вне картинки = «Готово».
5. Режим показа оригинала временный и не пишется в заметку. Пока он включён, размер картинки в тексте и высота строки пересчитываются по оригиналу, после выхода возвращаются к обрезанному виду без «прыжков» прокрутки (удерживать позицию картинки в окне).
6. Быстрый просмотр без правки: удержание клавиши (например, Alt) при наведении показывает оригинал во всплывающем окне, не меняя заметку. Необязательная функция, можно сделать позже.
7. У картинки без обрезки кнопки «Показать оригинал» нет (она не нужна, оригинал уже виден).

### Размер в заметке (кнопка «Размер»)

Меняет только отображаемый размер, файл не меняется.

1. Ручки на картинке (углы и стороны).
2. По умолчанию пропорции сохраняются. Удержание **Shift** временно снимает блокировку (можно растянуть без сохранения пропорций). Также есть переключатель «Сохранять пропорции» (замок) в панели.
3. Числовые поля «Ширина» и «Высота» в пикселях (и «%» от оригинала):
   - при включённых пропорциях ввод только ширины пересчитывает высоту автоматически, и наоборот;
   - при выключенных пропорциях ширина и высота независимы.
4. Кнопка «Сбросить размер» возвращает размер по умолчанию.
5. Значение пишется в ссылку: `![[имя.png|300]]` (только ширина, высота по пропорциям) или `![[имя.png|300x200]]` (оба значения). Если задан размер без сохранения пропорций, всегда писать `ШxВ`.
6. Размер относится к области после обрезки: если рамка обрезки изменилась, пропорции отображения пересчитываются по новой рамке.

### Сжатие (кнопка «Сжать»)

Открывает небольшое окно с настройками, ничего не применяется до подтверждения:

1. уменьшение разрешения («50%» или максимальная ширина);
2. выбор формата (PNG, WebP lossless, JPEG);
3. кнопка «Сжать сильнее»: оптимизация PNG без потерь (`oxipng`);
4. квантизация до 256 цветов (проверить лицензию).

Показывать размер до и после («1,8 МБ → 240 КБ») и предпросмотр. Кнопки «Применить» и «Отмена». Кодирование в фоне. Сжатие необратимо, перед применением показать предупреждение.

Сжатие применяется ко всему оригиналу. Если меняется разрешение, `crop` и координаты аннотаций в `.edit.json` пересчитываются пропорционально. Совет в окне: если обрезка уже готова, сначала «Применить обрезку окончательно», так файл станет меньше.

### Откат

- Пока заметка открыта, любое действие отменяется Ctrl+Z.
- Обрезка и аннотации после закрытия заметки остаются обратимыми (оригинал цел, правки в `.edit.json`).
- Необратимы только: «Применить обрезку окончательно», сжатие (перекодирование) и размытие. Перед каждым показывать подтверждение. Решить при реализации: предлагать флажок «Сохранить копию оригинала» (`имя.orig.png`, входит в пару файлов).

## Скругление углов

Необязательное оформление: углы картинки скруглены в заметке, при экспорте в Markdown и в PDF. Исходный файл не меняется.

### Хранение и настройки

- Глобальная настройка «Скругление углов изображений» (значение по умолчанию для всех картинок). Для этого `.edit.json` не нужен.
- Своё значение у картинки: `"corner_radius": 8` в `.edit.json`. Единица: проценты от меньшей стороны видимой области (после обрезки), от 0 до 50, где 0 = без скругления. Относительная единица нужна, чтобы скругление выглядело одинаково при любом размере картинки и при экспорте. Если поля нет, берётся значение из настройки.
- `.edit.json` создавать только при своём значении, отличном от настройки.

### Интерфейс

- Кнопка **«Скругление»** в панели картинки: пресеты «Нет», «Малое», «Среднее», «Большое», поле или ползунок в процентах, пункт «По умолчанию» (сбрасывает своё значение).
- Предпросмотр сразу на картинке в заметке.

### Показ в заметке

- Контейнер картинки со скруглёнными углами и отсечением содержимого по этой форме (в GPUI: скругление плюс `overflow_hidden`, проверить метод в используемой версии). Аннотации тоже отсекаются по скруглённой форме.
- Радиус считается от показанной области и пересчитывается сам при смене обрезки или отображаемого размера.
- В режиме «Показать оригинал» скругление не применять, там нужна полная картинка с рамкой обрезки.

### Экспорт

- **Markdown:** скругление в обычном Markdown не выразить, а `style="border-radius"` в ряде рендереров (например, GitHub) вырезается. Поэтому в копии картинки углы вырезаются по маске с прозрачностью (альфа-канал). У JPEG прозрачности нет: конвертировать копию в PNG или WebP либо залить углы цветом фона (настройка). Сжатие и квантизация PNG должны сохранять альфа-канал.
- В диалоге экспорта: «Скруглять углы» (включено, если скругление задано) и запасной вариант «HTML `<img style="border-radius">`» для рендереров, которые его понимают.
- Если подпись вшита в изображение, она остаётся прямоугольной полосой: скругляется только сама картинка.
- **PDF (Typst):** обернуть изображение в `block(clip: true, radius: ...)`, радиус перевести из процентов в абсолютную длину по размеру картинки на странице. Проверить параметры `radius` и `clip` в используемой версии Typst. Для PDF использовать этот способ, а не запечённый PNG, чтобы края оставались векторными.

## Аннотации (как в Lightshot), отдельным слоем

Инструменты: стрелка, линия, прямоугольник, эллипс, маркер-подсветка, карандаш, текст, нумерованные метки, размытие или пикселизация области. Цвет, толщина, заливка настраиваются. Выбор, перемещение, изменение размера, удаление, порядок слоёв, Ctrl+Z и Ctrl+Y.

### Хранение

- Оригинал `имя.png` лежит без аннотаций.
- Аннотации лежат векторно в `имя.edit.json` рядом с `crop`. Фигуры в координатах пикселей оригинала (тип, точки, цвет, толщина, текст, порядок).
- При показе в заметке аннотации рисуются поверх картинки. Файл `.png` остаётся чистым, слои можно менять и удалять позже.
- При «Применить обрезку окончательно» координаты сдвигаются (см. выше). Изменение отображаемого размера аннотации не затрагивает, они масштабируются вместе с картинкой.
- Команда «Свести слои» (flatten): записывает аннотации в пиксели, удаляет их из `.edit.json`. Нужна для отправки наружу и размытия.
- Экспорт заметки в другие редакторы: свести слои и применить обрезку в копии файла, оригинал не менять.

### Размытие и пикселизация

Это не слой в обычном смысле: если оставить базовую картинку чистой, скрытые данные (пароли, имена) можно восстановить, сняв слой. Для этих инструментов при подтверждении предупреждать и сразу применять к пикселям базового файла (необратимо), а не хранить как слой.

### Отрисовка

- В редакторе: рисовать фигуры в GPUI (элемент canvas, пути), проверить API в используемой версии.
- Сведение слоёв и экспорт: растеризовать в пиксели чисто-Rust библиотекой (`tiny-skia` или через SVG и `resvg`, который уже есть в стеке GPUI), проверить совпадение с экраном.
- Хит-тест и ручки выделения реализовать по геометрии фигур, не по пикселям.

## Подпись к изображению

Необязательный заголовок картинки над или под ней, например «Рис. 1. Схема стенда». Подпись хранится как метаданные в `имя.edit.json`, а не в тексте заметки.

### Хранение

- В `имя.edit.json`: `"caption": {"text": "Схема стенда", "position": "below", "numbered": true}` (`position`: `below` или `above`).
- **Номер не хранится.** Он вычисляется при показе и экспорте: по порядку картинок с подписью и `numbered: true` в заметке, сверху вниз. Вставка, удаление и перенос картинок перенумеровывают рисунки сами.
- Пустая подпись: удалить `caption` из файла.
- Подпись относится к файлу вложения и едет вместе с парой `.png` + `.edit.json` при copy, cut, переносе и корзине. В новой заметке номера пересчитываются.

### Показ и редактирование в заметке

- Подпись показывается под картинкой (или над, по настройке картинки), по центру, шрифтом мельче основного текста. Ширина не больше отображаемой ширины картинки, длинный текст переносится.
- Формат по шаблону из настроек: `Рис. {n}. {text}`. Префикс и разделитель настраиваются («Рис.», «Fig.», «Figure» и т.д.). Для подписи без номера выводится только `{text}`.
- Редактирование: кнопка **«Подпись»** в панели картинки или клик по самой подписи. Поле ввода прямо под картинкой: Enter сохранить, Esc отмена. Переключатели «Над / Под» и «Нумеровать».
- Только простой текст. Форматирование внутри подписи позже, если понадобится.
- Настройки: шаблон подписи, позиция по умолчанию (под картинкой), нумерация включена по умолчанию. Нумерация сквозная в пределах одной заметки.

### Экспорт

- В Markdown подпись выводится отдельным абзацем под картинкой (или над ней, если выбрано «Над») курсивом: `*Рис. 1. Схема стенда*`. В alt-текст ссылки подставляется сам текст: `![Схема стенда](attachments/имя.png)`.
- В диалоге экспорта выбор формата подписей: «курсивная строка» (по умолчанию), «HTML `<figure>` и `<figcaption>`», «только alt-текст».
- Номера в экспорте совпадают с номерами в редакторе. Картинки без подписи не нумеруются.
- Экспорт в PDF (через Typst): подпись передавать как `#figure(image(...), caption: [...])`. Нумерацию может вести Typst, проверить, что префикс («Рис.») и порядок совпадают с редактором.

### Вшивание подписи в изображение (необязательно)

Подпись можно не выводить отдельной строкой, а нарисовать в пикселях вместе со сведёнными аннотациями (стрелки, линии, текст). Получается одна готовая картинка с «Рис. 1. Название», которая выглядит одинаково везде: в GitHub, Word, мессенджерах, при «Сохранить как…».

- Где доступно: опция «Вшить подпись в изображение» в диалоге экспорта MD (по умолчанию выключена) и в командах «Сохранить как…» и «Копировать» для картинки.
- Что делает: в копии файла (оригинал и `.edit.json` не меняются) применяется обрезка, сводятся аннотации, затем к полотну добавляется полоса с подписью под картинкой или над ней (по `position`), чтобы текст не закрывал содержимое. Номер берётся актуальный на момент экспорта и дальше не меняется.
- Если подпись вшита, текстовую строку `*Рис. N. Текст*` под картинкой в Markdown не выводить (иначе будет дубль), alt-текст оставить.
- Оформление полосы: фон белый или прозрачный (настройка), цвет текста контрастный, размер шрифта пропорционален ширине картинки, перенос длинного текста по строкам, выравнивание по центру.
- Отрисовка текста в пикселях: растеризовать текст тем же средством, что и аннотации (шрифт и шейпинг: `cosmic-text` или текст через SVG и `resvg` со встроенным шрифтом), проверить кириллицу и совпадение с видом в редакторе.
- Минусы, о которых надо предупредить в диалоге: вшитый текст нельзя выделить, найти поиском или поправить, а номер остаётся тем, что был при экспорте.

### Оговорки

- Подпись лежит в JSON, поэтому не видна в исходном `.md` и в других редакторах до экспорта. Если `.edit.json` потерян, подпись пропадает. Альтернатива, если нужна видимость везде: хранить подпись в ссылке `![[имя.png|подпись]]` (формат Obsidian), но это уже не метаданные. Решить при реализации.
- Если нужен поиск по подписям, добавлять их в индекс вместе с текстом заметки.
- Ссылки на рисунки из текста («см. рис. 1») и список рисунков: позже.

## Экспорт заметки (пункт меню «Экспорт MD»)

Создаёт zip-архив с заметкой и её вложениями. Исходные файлы не меняются.

Состав архива:

```
имя-заметки.zip
├── имя-заметки.md
└── attachments/
    ├── 2026-10-31-1515-k3x9.png   (с применённой обрезкой и сведёнными аннотациями)
    └── ...
```

Алгоритм:

1. Разобрать заметку, собрать все ссылки на вложения (`![[имя]]`, `![](путь)`).
2. Для каждой найти файл через `resolve_attachment`. Включать только файлы, на которые ссылается эта заметка.
3. Изображения с `.edit.json`: в **копии** (PNG) применить обрезку, скругление углов (см. «Скругление углов») и свести слои, оригинал и `.edit.json` не трогать. Так обрезанные части не попадают в архив. Без правок: копировать как есть. Прочие вложения (PDF и т.д.): копировать как есть. Если в заметке задан размер (`|300`), его не применять к пикселям.
4. Переписать ссылки в экспортируемом `.md` (только в копии внутри архива, заметка в хранилище не меняется).

   Зачем: в заметке ссылка хранится в формате Obsidian, только с именем файла, без пути:

   ```
   ![[2026-10-31-1515-k3x9.png]]
   ```

   Другие редакторы (GitHub, VS Code, Typora) такую запись не понимают и покажут её текстом. Им нужен обычный Markdown с путём к файлу:

   ```
   ![](attachments/2026-10-31-1515-k3x9.png)
   ```

   Что делать: заменить все ссылки на вложения (картинки и прочие файлы) на стандартные Markdown-ссылки с путём `attachments/<имя>`. Этот путь совпадает с папкой, которую экспорт кладёт в тот же архив, поэтому после распаковки всё работает без правок.

   Детали:
   - Имена с пробелами, кириллицей и спецсимволами кодировать в пути (`пример файл.png` → `attachments/%D0%BF...`).
   - Разделитель пути всегда `/`, в том числе на Windows.
   - Подпись из `![[имя.png|подпись]]` переносить в альтернативный текст: `![подпись](attachments/имя.png)`. Если после `|` стоит число или `ШxВ`, это размер, а не подпись.
   - Размер `|300` или `|300x200`: переводить в `<img src="attachments/имя.png" width="300">` (и `height`, если задан) или отбрасывать (решить при реализации).
   - Вложения, не являющиеся картинками (PDF и т.д.): обычная ссылка `[имя.pdf](attachments/имя.pdf)`, без `!`.
   - Подписи к изображениям из `.edit.json`: выводить по правилам раздела «Подпись к изображению» (абзац `*Рис. N. Текст*` под или над картинкой, текст в alt, номера по порядку в заметке). Если включена опция «Вшить подпись в изображение», подпись рисуется в самой копии картинки вместе со сведёнными аннотациями, а отдельная строка не выводится.
   - В диалоге экспорта опция «Оставить ссылки Obsidian (`![[ ]]`)», по умолчанию выключена. При включении ссылки не переписываются, имена файлов остаются те же.
5. Ссылки на другие заметки (`[[Заметка]]`): оставить как текст, в диалоге показать предупреждение, что они не включены.
6. Не найденные вложения: ссылку не менять, перечислить в итоговом сообщении («не найдено: N»).
7. Записать zip: пути с `/`, имена в UTF-8, изображения без повторного сжатия (store), текст с deflate. Крейт `zip` (проверить актуальную версию и фичи).
8. Выбор места сохранения стандартным диалогом, имя по умолчанию по названию заметки. Работа в фоне, прогресс при большом числе файлов. По завершении «Показать в папке».

Критерии: распакованный архив открывается в любом Markdown-редакторе с работающими картинками и без обращения к исходному хранилищу. Аннотации видны на картинках, обрезанные части в файлах отсутствуют. В архиве нет вложений других заметок.

## Технологические решения и архитектурные ограничения

Решения ниже фиксируются до начала реализации, чтобы не делать архитектурный рефакторинг на поздних этапах. Версии и API крейтов проверить на docs.rs перед подключением.

### Стек

| Задача | Решение |
|---|---|
| Отображение изображений | GPUI `img()` |
| Выделение, рамки, ручки, мышь, векторный холст | GPUI `canvas()`, `div()` и события по эталону `examples/brush` (`PathBuilder`, `paint_path`) |
| UI-компоненты (панели, тулбары, поповеры, диалоги, тосты, контролы) | GPUI Kit (`crates/component`, `crates/base`): `Toolbar`, `Popover`, `Dialog`, `Notification`, `ButtonGroup`, `Slider`, `Switch`, `NumberInput`, `ContextMenuExt`, `Badge`, `Tag`, `ColorPicker` |
| Декодирование, crop, resize | `image` (отключить ненужные форматы через фичи) |
| Стрелки, фигуры, маски, скругления (растеризация при экспорте) | `tiny-skia` |
| Текстовые аннотации и вшитая подпись | `cosmic-text` (shaping, переносы) или `ab_glyph` (простой текст); выбрать один |
| Оптимизация PNG | `oxipng`, за фичей Cargo |
| Экспорт заметки в ZIP | `zip`, за фичей Cargo |
| Lossy WebP | не делать, пока нет запроса. Встроенный кодировщик WebP в `image` по документации (0.25.10) только lossless, для lossy нужен отдельный кодировщик на базе libwebp |
| Квантизация PNG | отдельно, проверить лицензию (`imagequant`) |
| Буфер обмена | отдельный адаптер (trait) с реализациями под платформы |

Не добавлять `imageproc` и `resvg` специально ради редактора. `resvg` уже есть в стеке GPUI и не должен быть обязательным звеном обработки изображений. OpenCV и внешние графические редакторы не использовать. По правилам [AGENTS.md](../../AGENTS.md) («новые компоненты не создаются»), все элементы интерфейса берутся из существующей кодовой базы или готовых компонентов GPUI Kit (`D:\Naben\Github\rust\gpui-examples\gpui-kit`).

### Ограничение 1. Единая геометрия аннотаций

- Не должно быть двух независимых реализаций стрелок, линий и фигур.
- Общая промежуточная модель путей: из модели аннотации (`arrow`, `rectangle`, `ellipse`, ...) строится набор отрезков и кривых (наконечник стрелки, скругление концов, толщина).
- GPUI (`canvas()`) и `tiny-skia` только заливают или обводят эти готовые пути. Хит-тест и ручки выделения тоже строятся по этим путям.
- Скругление углов картинки и отсечение аннотаций использует ту же модель контура.

### Ограничение 2. Детерминированный текст

- Один встроенный в приложение шрифт (с кириллицей) для аннотаций и подписей, вшитых в картинку. Системные шрифты не использовать, иначе результат на разных системах разный.
- Один общий слой подготовки текста: раскладка (шейпинг, переносы, метрики) считается в одном месте, а GPUI и растеризатор получают готовые глифы или контуры. Два независимых механизма верстки не допускаются.
- В первой версии текстовая аннотация может быть ограничена простым текстом с фиксированной шириной переноса.

### Ограничение 3. Производительность

- Декодирование, обработка, сжатие и экспорт выполняются в фоновых задачах, интерфейс не блокируется.
- Для показа держать уменьшенные превью (под размер на экране) с кэшем. Полный оригинал загружать по необходимости: режим обрезки, «Показать оригинал», экспорт.
- Аннотации не растеризовать при каждом изменении. Пока пользователь редактирует, они хранятся в модели и рисуются поверх оригинала. Растеризация только при экспорте, «Свести слои» или создании финальной копии.
- Большие картинки не держать в памяти в нескольких копиях.

### Ограничение 4. Формат правок независим от графического движка

- `имя.edit.json` (`crop`, `annotations`, `corner_radius`, `caption`) описывает правки в терминах предметной области: координаты в пикселях оригинала, проценты, текст. Никаких типов GPUI, `tiny-skia` или `cosmic-text` в формате.
- Это позволяет позже заменить GPUI или механизм экспорта, не меняя хранимые заметки.
- В файле поле `version`. Читать старые версии, неизвестные поля сохранять при перезаписи, повреждённый файл не должен ронять приложение (показать картинку без правок и предупреждение).

### Ограничение 5. Адаптеры платформы

- Получение изображения из буфера обмена вынести в отдельный модуль, не смешивать с логикой вставки в заметку.
- Заранее проверить поддержку изображений в буфере в используемой версии GPUI и на Windows, и на Linux.

### Обязательные тесты

- Эталонные изображения для всех типов аннотаций (рендер `tiny-skia` сравнивается с эталоном с допуском).
- Совпадение геометрии при отображении и экспорте (одни и те же пути).
- Кириллица и встроенный шрифт: рендер, переносы, масштабирование, одинаковый результат на разных системах.
- Crop и координаты: после изменения рамки, применения обрезки, смены разрешения при сжатии и изменения отображаемого размера.
- Скругление углов: прозрачные углы в экспортированном PNG, сохранение альфа-канала после `oxipng`.
- Автонумерация подписей при вставке, удалении и переносе картинок.
- Чтение `.edit.json` старых версий и повреждённого файла.
- Буфер обмена на Windows и Linux (ручной чек-лист, если автоматизировать нельзя).

## Этапы

1. Вставка из буфера, запись PNG в `attachments/` рядом, ссылка по имени, `resolve_attachment` с шагами 1, 3, 5.
2. Размер в заметке: ручки, Shift, переключатель пропорций, числовые поля (авто-подстройка второй стороны), запись `|W` и `|WxH`.
3. Недеструктивная обрезка: `.edit.json`, рамка с ручками, соотношения сторон (список, свой `W:H`, «⇄»), Shift, числовые поля, показ обрезанного вида в заметке, значок «обрезано», кнопка «Показать оригинал» с правкой рамки на месте, «Готово», «Отмена», «Сбросить».
4. «Применить обрезку окончательно» с подтверждением. С этого этапа и далее все файловые операции работают с парой `.png` + `.edit.json`.
5. Сжатие: формат, качество, понижение разрешения (пересчёт `crop`), предпросмотр размера.
6. Cut/Copy/Paste между заметками с переписыванием ссылок и копированием пары файлов.
7. Корзина, отложенное удаление при сохранении, возврат из корзины (для пары файлов).
8. Словарь по хранилищу (шаг 4 поиска), команда «Найти неиспользуемые вложения».
9. Перенос заметки с вложениями. Экспорт MD в zip с применением обрезки в копиях.
10. Жёсткое сжатие (`oxipng`, квантизация).
11. Аннотации: модель данных в `.edit.json`, стрелка, прямоугольник, линия, текст, выбор и удаление, отмена.
12. Остальные инструменты (эллипс, маркер, карандаш, метки), «Свести слои», размытие с необратимым применением. Экспорт: сведение аннотаций в копиях.
13. Скругление углов: настройка по умолчанию, `corner_radius` у картинки, кнопка и предпросмотр, отсечение в заметке, запекание с прозрачностью при экспорте в Markdown, `block(clip, radius)` в PDF. Можно делать после этапа 4.
14. Подписи к изображениям: `caption` в `.edit.json`, показ и редактирование, автонумерация, шаблон в настройках, вывод при экспорте. Можно делать сразу после этапа 4, когда `.edit.json` уже есть.

## Критерии готовности

- Скриншот вставляется без диалогов, обрезка и сжатие запускаются кнопками и не навязываются.
- Обрезку можно открыть позже и сдвинуть границы, пока она не применена окончательно. Оригинал при этом цел.
- Кнопка «Показать оригинал» разворачивает полную картинку в заметке с затемнением вне рамки, рамка правится на месте, возврат к обрезанному виду не сбивает прокрутку.
- «Применить обрезку окончательно» требует подтверждения и после этого необратима.
- Размер меняется с сохранением пропорций и без них (Shift или переключатель). Ввод одной стороны подстраивает другую, если пропорции включены.
- Обрезка по соотношению `10×15`, `2×3`, `4×3` и своему `W:H`, а также по числовым полям работает без выхода за границы картинки.
- Папка с заметками и `attachments/` копируется в другое место, все картинки и их правки на месте.
- Копирование и вставка ссылки в другую заметку не ломает исходную.
- Удаление ссылки и Ctrl+Z не теряют файл.
- Открытие заметки без записи на диск, копирование в `attachments/` только при сохранении.
- Битая ссылка отображается как битая, без падений.
- Углы картинок можно скруглять (настройка по умолчанию и своё значение у картинки), скругление видно в заметке, в экспортированных картинках (прозрачные углы) и в PDF.
- Подпись над или под картинкой хранится в `.edit.json`, номера «Рис. N» считаются автоматически и обновляются при добавлении и удалении картинок. В экспортированном Markdown под картинкой стоит строка «Рис. N. Текст».
