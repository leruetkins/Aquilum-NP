Этот документ описывает всё, что **не зависит от языка плагина**: цели, архитектуру хоста, манифест, права и безопасность, проверку плагинов перед запуском, раскладку и панели, формат дерева UI, этапы работ и каталог.

| `plugins-00-core.md` (этот) | общее ядро и дорожная карта |
| `plugins-01-js-obsidian.md` | JS/TS-плагины (QuickJS) с API в стиле Obsidian |

Ссылки вида «core §12.4» ведут в этот документ, «JS §6» в JS-документ, «WASM §4» в WASM-документ, «Zed §3» в документ по Zed.

> Код в разделе 12 это **эскизы для проектирования**, они не проверялись компиляцией. API GPUI, `rquickjs` и `wasmtime` быстро меняются: закрепите версии в `Cargo.toml` и сверяйте сигнатуры по актуальной документации.

## 0. Цели и принципы

**Цель:** пользователи пишут плагины сами, без правки исходников приложения, безопасно и с быстрым циклом разработки.

**Принципы:**
- Ядро (vault, заметки, индекс, события) не зависит от GPUI.
- Плагин никогда не получает прямого доступа к GPUI, файловой системе или сети. Только через API хоста с проверкой прав.
- UI-поток никогда не блокируется плагином.
- API версионируется, обратная совместимость в рамках major.
- Сначала маленький стабильный API, потом расширения. Убрать метод из API нельзя, добавить можно.

**Не цели (на старте):** полная совместимость с готовыми плагинами Obsidian (они завязаны на DOM), нативные dylib-плагины. Каталог плагинов планируется на этапе 8 по модели Obsidian.

## 1. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Язык плагинов | JavaScript / TypeScript | Знаком аудитории Obsidian, огромный пул разработчиков |
| Рантайм | `rquickjs` (QuickJS), один рантайм на плагин | Лёгкий, есть лимиты памяти и прерывание по таймауту |
| Модель выполнения | Рантайм плагина в отдельном потоке, связь с UI через каналы | Состояние GPUI не `Send`, плагин не должен блокировать UI |
| UI плагинов | Декларативное дерево компонентов (JSON), рендерит хост | Контроль внешнего вида, стабильность при обновлении GPUI |
| Права | Манифест + подтверждение пользователем, проверка в хосте | Принцип наименьших привилегий |
| Второй рантайм | WASM (`wasmtime` + WIT), позже, см. `plugins-02-wasm.md` | Для тяжёлых плагинов на Rust и других языках |
| Стиль API | Названия и сигнатуры как в Obsidian, но без DOM и CodeMirror (JS §2.3) | Простое портирование логики плагинов, без чужой архитектуры |
| Контракт рантайма | Общий трейт `PluginRuntime` и фабрика `RuntimeFactory` (core §12.1): мост, права, реестр, раскладка и проверка не знают, JS это или WASM | Второй рантайм это адаптер, а не переделка |

## 2. Архитектура

### 2.1 Крейты и стратегия перехода

Текущая кодовая база `aquilum-gpui` представляет собой **один монолитный крейт** `vibecodium`. Чтобы не блокировать разработку плагинов тяжелым распилом проекта на месяц, архитектура реализуется в две фазы:

**Фаза A (Старт разработки): Модульная структура внутри текущего крейта**
```
aquilum-gpui/src/
├─ vault.rs          # VaultCore, FileInfo, безопасные пути без зависимости от GPUI
├─ events.rs         # EventBus: VaultEvent, WorkspaceEvent
├─ commands.rs       # CommandRegistry (общий для встроенных команд и плагинов)
├─ ribbon.rs         # Реестры RibbonAction и StatusBarItem
├─ plugins/          # Хост и рантайм плагинов
│   ├─ bridge.rs     # Асинхронный мост GPUI (start_plugin_bridge)
│   ├─ ui.rs         # UiNode и GPUI-рендер
│   ├─ runtime.rs    # QuickJS рантайм
│   └─ manifest.rs   # Парсинг manifest.json и права
└─ views/            # Существующий UI (AppView, right_sidebar.rs с монтированием PluginView)
```

**Фаза B (Целевая): Выделение в workspace**
```
workspace/
├─ core/            # vault, заметки, ссылки, теги, поиск, события. Без GPUI
├─ plugin-api/      # типы API (serde), версия API, определения прав
├─ plugin-host/     # загрузка, права, мост к UI, реестр регистраций. Без GPUI-типов
├─ plugin-runtime-js/    # QuickJS-рантайм (plugins-01-js-obsidian.md)
├─ plugin-runtime-wasm/  # wasmtime-рантайм (plugins-02-wasm.md)
├─ plugin-verify/   # проверка плагинов перед запуском (core §6.1)
├─ app/             # GPUI-приложение, рендерит UI плагинов
└─ sdk/             # TypeScript SDK: .d.ts, шаблон плагина, CLI
```

### 2.2 Поток данных

```
Плагин (QuickJS или wasmtime, свой поток)
   │  вызов api.vault.read(path)   [Promise]
   ▼
plugin-host: проверка прав → сообщение в канал
   │
   ▼
UI-поток (GPUI): cx.spawn принимает запрос → core выполняет → ответ в канал
   │
   ▼
plugin-host: resolve Promise в рантайме плагина
```

Правила:
- Все вызовы API асинхронные (Promise).
- События хоста (сохранение заметки и т.п.) доставляются плагинам рассылкой по каналам.
- Каждое сообщение содержит `plugin_id` и `request_id`.

### 2.3 Структура папок

```
<vault>/.vault/plugins/<plugin-id>/
├─ manifest.json
├─ main.js          # собранный бандл
├─ styles.json      # необязательно: токены стилей
└─ data.json        # настройки/данные плагина (пишет хост)
```

## 3. Манифест

```json
{
  "id": "word-counter",
  "name": "Word Counter",
  "version": "1.0.0",
  "apiVersion": "1.0",
  "runtime": "js",
  "minAppVersion": "0.3.0",
  "author": "name",
  "description": "Счётчик слов в статус-баре",
  "main": "main.js",
  "permissions": {
    "vault": "read",
    "network": [],
    "process": false
  }
}
```

Поле `runtime`: `js` (по умолчанию) или `wasm`. Для `wasm` поле `main` указывает на `main.wasm` (компонент WASM, см. `plugins-02-wasm.md`). Права, лимиты и проверки одинаковы для обоих рантаймов.

Поля прав:
- `vault`: `none | read | write`
- `network`: список разрешённых доменов (пусто = нет доступа)
- `process`: запуск внешних процессов (по умолчанию `false`, отдельное явное подтверждение)

## 4. Публичный API

Публичный API зависит от языка плагина, поэтому описан в документах рантаймов:
- **JS/TS:** JS §2. Названия и сигнатуры как в Obsidian, но без DOM и CodeMirror.
- **WASM:** WASM §3. Тот же набор возможностей в виде интерфейса WIT (`host` и `plugin`).

**Общие принципы для любого рантайма:**
1. Один набор запросов и событий (`ApiRequest`, `HostEvent`, core §12.2): второй язык это адаптер, а не новый API.
2. Все операции, которые меняют состояние или ходят за пределы снимка, асинхронные. Синхронные только геттеры по снимку состояния только для чтения (core §12.5).
3. Каждый вызов проходит проверку прав (core §12.3) в хосте, а не в плагине.
4. Все регистрации (команды, подписки, виды, ленты, окна) снимаются хостом при выгрузке плагина автоматически (core §12.10).
5. API версионируется по семверу (`apiVersion` в манифесте). Убрать метод нельзя, добавить можно.
6. Неподдерживаемая возможность даёт явную ошибку, а не `undefined`.

## 5. Декларативный UI

Плагин возвращает дерево, хост рендерит его на GPUI и присылает события обратно. Примеры кода на JS: JS §3. Формат дерева и проверка в Rust: core §12.7. Представление для WASM: WASM §3.

Набор компонентов v1: `column`, `row`, `text`, `markdown`, `list`, `button`, `input`, `checkbox`, `select`, `separator`, `tabs`.

Правила:
- Компоненты и стили ограничены токенами темы (цвета, отступы), а не произвольными значениями.
- Дерево дифится на стороне хоста, перерисовывается только изменённое.
- Для нестандартных случаев позже: «холст» с примитивами рисования.

### 5.1 Модальные окна, диалоги и кнопки

Плагин не создаёт окна GPUI сам. Он описывает содержимое деревом компонентов, а хост показывает его в собственной рамке и присылает события обратно. Пример на JS в стиле Obsidian (`Modal`, `onOpen`, `open`, `close`): JS §3.2.

**Что плагин может создавать:**

| Что | Версия |
|---|---|
| Кнопки в модальных окнах, панелях и формах настроек (`button`, варианты `default`, `primary`, `danger`) | v1 |
| `Modal` | v1 |
| Готовые диалоги: подтверждение, ввод строки, выбор из списка (`SuggestModal`) | v1 |
| Кнопки на ленте и в статус-баре, пункты в палитре команд | v1 |
| Контекстные меню (`Menu`) | после v1 |
| Отдельные окна ОС (popout), возможно как право `ui.window` с обязательной рамкой хоста | не на старте |

**Правила хоста:**
1. Рамку и заголовок рисует хост, в заголовке всегда название плагина. Окно плагина нельзя выдать за системный диалог (в том числе за диалог прав).
2. Стили только из токенов темы, без произвольных цветов и отступов.
3. Ограничения: максимальный размер окна, одно модальное окно от плагина одновременно, лимит частоты открытия, закрытие по Esc и клику вне окна, управление фокусом.
4. Окна закрываются при выгрузке плагина вместе с остальными регистрациями.
5. Состояние полей ввода хранится на стороне хоста. Плагин получает значение по событию (`onChange` с задержкой или `onSubmit`), иначе каждая буква шла бы через поток плагина и ввод лагал бы.

### 5.2 Панели в интерфейсе и размещение (предложение, модель как у Obsidian)

**Модель расположения (должна жить в ядре приложения, а не в плагинах):**
- Рабочая область состоит из **центральной области** (редактор, вкладки и разделения) и **левой и правой боковых панелей**. Позже, возможно, нижняя панель.
- В каждой области есть **группы вкладок**, а во вкладке («leaf») лежит один **вид** (`View`).
- Встроенные панели (файлы, поиск, граф, обратные ссылки) и панели плагинов строятся **на одном и том же механизме видов**. Так API гарантированно подходит для реальных панелей.

**Где плагин может разместить своё:**

| Место | Как | Версия |
|---|---|---|
| Левая или правая боковая панель | `workspace.getLeftLeaf()` / `getRightLeaf()` + `setViewState` | v1 |
| Центральная область (как вкладка заметки) | `workspace.getLeaf()` + `setViewState` | v1 |
| Заголовок вида (кнопки действий) | `view.addAction(icon, title, callback)` | v1 |
| Лента, статус-бар, палитра команд | `addRibbonIcon`, `addStatusBarItem`, `addCommand` | v1 |
| Панель инструментов внутри вида | компонент `toolbar` с кнопками в дереве | v1 |
| Тулбар редактора, заголовок заметки, контекстное меню файлов | отдельные точки расширения | после v1 |
| Нижняя панель | отдельная область | позже |

Имена методов в колонке «Как» даны в стиле JS-SDK (JS §2). Для WASM те же возможности доступны через функции интерфейса `host` (WASM §3). Пример кода: JS §3.3.


**Что делает хост, а что плагин:**
- Хост: рамка панели, вкладки, перетаскивание между областями, изменение размера, сворачивание, закрытие, фокус, иконка и название плагина.
- Плагин: только содержимое вида и действия в его заголовке.
- Плагин не может рисовать поверх интерфейса хоста или вне своих мест (никаких оверлеев и «плавающих» кнопок).

**Сохранение расположения:**
- Хост сохраняет раскладку (какие виды где, размеры, активные вкладки) в `.vault/workspace.json` вместе с `getState()` каждого вида.
- При запуске вид восстанавливается через `setState()`.
- Если плагин отключён или удалён, на месте панели показывается заглушка «Плагин X не установлен» (с кнопкой установки из каталога), а раскладка не ломается.

**Ограничения:** лимит видов на плагин, минимальные размеры, ограничение частоты `render`, размера дерева компонентов, число действий в заголовке.

## 6. Безопасность

1. **Песочница:** в рантайме нет `fs`, `net`, `process`. Доступно только то, что хост явно подставил.
2. **Права:** проверка при каждом вызове API, а не только при установке.
3. **Пути:** vault-доступ нормализуется, `..` и симлинки наружу блокируются.
4. **Сеть:** allowlist доменов из манифеста, запрещены редиректы на чужие домены.
5. **Лимиты:** память (`set_memory_limit`), время выполнения (interrupt handler), размер сообщений, частота вызовов.
6. **Изоляция сбоев:** паника или таймаут отключают только этот плагин, пользователь получает уведомление.
7. **Подтверждение:** при установке и при изменении прав в обновлении показывается список прав.
8. **Данные плагина:** `data.json` у каждого плагина свой, плагины не видят данные друг друга.
9. **Безопасный режим:** флаг запуска без плагинов (на случай поломанного плагина).
10. **Окна и диалоги плагинов:** рамка и заголовок с названием плагина рисуются хостом (нельзя подделать системный диалог или диалог прав), одно модальное окно от плагина одновременно, лимит частоты открытия, максимальный размер, автоматическое закрытие при выгрузке плагина (раздел 5.1).


### 6.1 Проверка плагина перед запуском (verify)

**Нужна, но как дополнительный слой, а не замена песочницы.** Доказать по коду, что программа «не сделает лишнего», нельзя в общем случае: имя вызова можно собрать из частей строки, код может ждать определённой даты или файла и вести себя иначе, когда понимает, что его проверяют. Поэтому защита держится на двух уровнях:

1. **Жёсткие ограничения во время работы** (пункты 1–10 выше, core §12.2–12.4): песочница, права, лимиты, страйки. Они работают всегда и не зависят от результата проверки.
2. **Проверка перед запуском:** рано и дёшево отклоняет очевидно плохие плагины, ловит ошибки интеграции (сломанный `onload`, утечки при выгрузке, невалидное дерево UI) и даёт автору понятный отчёт.

**Этапы verify** (одна схема для любого рантайма):

| Этап | Что проверяется | Результат |
|---|---|---|
| 1. Манифест | JSON Schema, `id` по маске, `runtime`, `apiVersion` поддерживается, `minAppVersion` не выше версии приложения, права из допустимого набора | ошибка: отклонить |
| 2. Размер и формат | лимит размера бандла (стартово JS 5 МБ, WASM 20 МБ), корректная кодировка или валидный бинарник | ошибка |
| 3. Статическая проверка бандла | зависит от рантайма. JS: компиляция без выполнения и разбор AST (JS §6.1). WASM: валидация модуля, версия API, разбор импортов и экспортов (WASM §6) | ошибка или предупреждение |
| 4. Пробный запуск (dry-run) | `onload`, `render` видов, клики и ввод, типовые события, команды, `onunload` в одноразовой песочнице на моковом приложении с жёсткими лимитами | ошибка или предупреждение |
| 5. Проверка выгрузки | после `onunload` и снятия регистраций в реестре ничего не осталось | ошибка |

**Пробный запуск (dry-run).** Выполняется в отдельном рантайме с жёсткими лимитами, на моковом приложении (`MockHost`, core §12.14): запись никуда не уходит, сеть отключена, vault состоит из нескольких типовых заметок.
1. `onload()` под дедлайном (стартово 500 мс) и лимитом памяти (стартово 32 МБ для JS, 64 МБ для WASM). Исключение, таймаут или превышение памяти это ошибка.
2. Подсчёт регистраций (команды, подписки, виды, ленты). Больше лимита (стартово 50 на тип) это ошибка.
3. Для каждого вида вызывается `render` с пустым состоянием, дерево проходит `validate_tree` (core §12.7). По каждой кнопке имитируется клик, по каждому полю ввода изменение.
4. Каждой подписке отправляется типовое событие, каждая команда вызывается один раз. Исключения здесь это **предупреждение**, потому что плагин мог рассчитывать на другие данные.
5. `onunload()`, затем выполняются все «освобождаемые» объекты (core §12.10). Если в реестре что-то осталось (подписка, вид, окно), это ошибка.
6. В отчёт попадают время вызовов, пиковая память и число обращений к API.

**Политика.**
- Ошибки блокируют установку и запуск. Плагин получает статус «Отклонён» с отчётом, который видит пользователь.
- Предупреждения показываются в диалоге прав и в отчёте. Они не блокируют запуск: эвристики (права, обфускация) дают ложные срабатывания, и из-за них нельзя ломать нормальные плагины.
- Один крейт `plugin-verify` используется приложением, CLI SDK (`plugin check`) и CI каталога (этап 8). Автор видит те же ошибки до публикации. Для каталога CI предупреждения про обфускацию считаются ошибками.

**Кэш и запуск.** Результат хранится в папке данных приложения (не в vault, чтобы плагин и синхронизация не могли его подменить) по ключу `sha256` бандла и версии хоста. Если хэш совпал и проверка прошла, плагин загружается без пробного запуска, так что старт остаётся быстрым. Иначе проверка выполняется в фоне, а плагин показывается как «Проверяется». Повторная проверка нужна после обновления плагина или приложения.

**Защита от падения при старте (boot guard).** Перед загрузкой плагина создаётся файл-маркер, он удаляется через несколько секунд после успешной работы. Если приложение упало в этот промежуток, при следующем запуске плагин с маркером автоматически отключается, а пользователь получает сообщение. Это страхует от того, что проверка и лимиты чего-то не поймали.

**Чего проверка не гарантирует.**
- Поведение, зависящее от времени, окружения или файлов, она не увидит.
- Движок плагина (QuickJS написан на C, `wasmtime` на Rust, но тоже не безошибочен) работает в том же процессе. Баг в самом движке теоретически может уронить приложение. Для v2 можно вынести рантаймы в отдельный процесс с IPC: сообщения `ApiRequest` и `HostEvent` уже сериализуемые, так что API при этом переделывать не придётся.

## 9. Риски и решения

| Риск | Что делать |
|---|---|
| Нестабильный API ломает плагины | Семвер API, `minAppVersion`, deprecation-цикл минимум на один major |
| UI из плагина тормозит | Дифф дерева, ограничение частоты `render`, лимит размера дерева |
| Состояние GPUI не `Send` | Только каналы и `cx.spawn`, никакого шаринга сущностей с потоками плагинов |
| Вредоносные плагины | Права, песочница, подтверждение, безопасный режим, позже ревью каталога |
| Слишком бедный API | Расширять по запросам сообщества, внутренние фичи сначала писать на том же API |
| Сложность редакторных хуков | Отложить до этапа 6, сначала довести ядро и UI-слой |
| Проверка даёт ложное чувство безопасности | Считать её дополнительным слоем: основная защита это песочница, права и лимиты (core §6.1) |
| Ложные срабатывания проверки блокируют нормальные плагины | Различать ошибки и предупреждения, давать автору отчёт и `plugin check`, не блокировать из-за эвристик вне каталога |
| Баг в движке (QuickJS, wasmtime) роняет приложение | Boot guard, отключение после падения, в v2 вынос рантаймов в отдельный процесс (сообщения уже сериализуемые) |

> Код ниже это эскизы для проектирования. Часть про JS-рантайм в JS §4, часть про WASM-рантайм в WASM §4, обоснования заимствований из Zed в Zed §3–5.

### 12.1 Контракт рантайма: один хост, несколько языков плагинов

Хост (мост, права, реестр регистраций, раскладка, проверка) работает с плагином только через трейт и не знает, JS это или WASM. Тогда второй рантайм это адаптер, а не переделка.

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum RuntimeKind { Js, Wasm }

pub struct SpawnSpec {
    pub id: PluginId,
    pub manifest: Manifest,
    pub bundle: Vec<u8>,          // main.js или main.wasm
    pub limits: Limits,           // core §12.14
}

/// Один запущенный плагин.
pub trait PluginRuntime: Send {
    fn kind(&self) -> RuntimeKind;
    /// Доставить событие плагину. Не блокирует вызывающего.
    /// HostEvent::Response обрабатывается рантаймом сам (разрешает ожидающий Promise или future).
```

```rust
    weak_app: gpui::WeakEntity<crate::views::app_view::AppView>,
    mut api_rx: futures::channel::mpsc::UnboundedReceiver<ApiCall>,
    cx: &mut gpui::App,
) {
    cx.spawn(async move |mut cx| {
        while let Some(call) = api_rx.next().await {

                if let Some(app) = weak_app.upgrade() {
                    app.update(cx, |this, cx| {
                        this.handle_plugin_call(call, cx);
                    });
                    true
                } else {
                    false
                }

                break; // Окно закрыто или AppView уничтожен
            }
        }
    })
    .detach();
}
```

### 12.3 Права

```rust
#[derive(Deserialize, Clone)]
pub struct Permissions {
    pub vault: VaultAccess,
    #[serde(default)] pub network: Vec<String>,
    #[serde(default)] pub process: bool,
}

#[derive(Deserialize, Clone, Copy, PartialEq, PartialOrd)]
#[serde(rename_all = "lowercase")]
pub enum VaultAccess { None, Read, Write }

impl Permissions {
    pub fn allow(&self, req: &ApiRequest) -> Result<(), ApiError> {
        match req {
            ApiRequest::VaultRead { .. } if self.vault >= VaultAccess::Read => Ok(()),
            ApiRequest::VaultModify { .. } if self.vault >= VaultAccess::Write => Ok(()),
            ApiRequest::Http { url, .. } => self.check_host(url),
            ApiRequest::Notice { .. }
            | ApiRequest::SetViewTree { .. }
            | ApiRequest::OpenModal { .. }
            | ApiRequest::OpenFile { .. } => Ok(()),
            _ => Err(ApiError::denied("permission denied")),
        }
    }

    fn check_host(&self, url: &str) -> Result<(), ApiError> {
        let host = url::Url::parse(url).ok().and_then(|u| u.host_str().map(str::to_owned))
            .ok_or_else(|| ApiError::denied("bad url"))?;
        let ok = self.network.iter().any(|d| host == *d || host.ends_with(&format!(".{d}")));
        if ok { Ok(()) } else { Err(ApiError::denied("domain not allowed")) }
    }
}

/// Права расширились? Нужно для диалога при обновлении (этап 8).
pub fn permissions_expanded(old: &Permissions, new: &Permissions) -> bool {
    new.vault > old.vault
        || (new.process && !old.process)
        || new.network.iter().any(|d| !old.network.contains(d))
}
```

Правила: редиректы при `Http` проверяются заново для каждого нового хоста; размер ответа ограничен (например, 10 МБ); таймаут запроса 30 с.

### 12.4 Безопасные пути (алгоритм по схеме Zed, подробности в Zed §3.1)

Схема Zed: лексическая нормализация, затем `canonicalize` ближайшего существующего предка (чтобы раскрыть симлинки), затем добавление оставшегося «хвоста» и проверка, что результат лежит внутри разрешённой папки. Это работает и для файлов, которых ещё нет.

```rust
pub fn resolve_in_vault(root_canon: &Path, rel: &str) -> Result<PathBuf, PathError> {
    // 1. отсеять мусор
    if rel.contains('\0') { return Err(PathError::Invalid); }
    let rel_path = Path::new(rel);
    if rel_path.is_absolute() || rel_path.has_root() { return Err(PathError::Absolute); }

    // 2. лексическая нормализация без обращения к ФС
    let mut stack: Vec<&OsStr> = Vec::new();
    for c in rel_path.components() {
        match c {
            Component::Normal(s) => stack.push(s),
            Component::CurDir => {}
            Component::ParentDir => { if stack.pop().is_none() { return Err(PathError::Escapes); } }
            Component::Prefix(_) | Component::RootDir => return Err(PathError::Absolute),
        }
    }
    let joined = stack.iter().fold(root_canon.to_path_buf(), |p, s| p.join(s));

    // 3. раскрыть симлинки у ближайшего существующего предка
    let mut existing = joined.as_path();
    let mut tail: Vec<OsString> = Vec::new();
    let canon_prefix = loop {
        match dunce::canonicalize(existing) {     // dunce убирает \\?\ на Windows
            Ok(p) => break p,
            Err(_) => {
                tail.push(existing.file_name().ok_or(PathError::Invalid)?.to_owned());
                existing = existing.parent().ok_or(PathError::Invalid)?;
            }
        }
    };
    let mut resolved = canon_prefix;
    for part in tail.into_iter().rev() { resolved.push(part); }

    // 4. итог должен остаться внутри vault
    if !resolved.starts_with(root_canon) { return Err(PathError::Escapes); }

    // 5. служебная папка: плагин не пишет в .vault/ (кроме своих данных через saveData)
    if resolved.starts_with(root_canon.join(".vault")) { return Err(PathError::Reserved); }
    Ok(resolved)
}
```

Обязательные тесты (по образцу тестов Zed): симлинк наружу, `..` наружу, симлинк в глубине несуществующего пути, новый файл во вложенной несуществующей папке (должен проходить), абсолютный путь, путь с `\0`, Windows-варианты (`C:\`, `\\server\share`, `..\..`, регистр букв).

**Известное ограничение:** между проверкой и открытием файла симлинк можно подменить (TOCTOU). Для v1 это принимается как остаточный риск, для усиления позже можно открывать файлы с запретом следования по симлинкам там, где ОС это позволяет.

### 12.5 Снимок состояния для синхронных геттеров

`getActiveFile()`, `getMarkdownFiles()`, `metadataCache` должны быть синхронными (как в Obsidian), а плагин живёт в другом потоке. Решение: неизменяемый снимок за `ArcSwap`.

```rust
pub struct Snapshot {
    pub version: u64,
    pub active_file: Option<FileInfo>,
    pub files: Arc<[FileInfo]>,
    pub meta: Arc<HashMap<String, FileCache>>,   // path -> ссылки, теги, frontmatter, заголовки
}

// хост (UI-поток или фоновая задача индексатора)
fn publish(&self, new: Snapshot, event: HostEvent) {
    self.snapshot.store(Arc::new(new));      // 1) сначала снимок
    for p in &self.plugins { let _ = p.events_tx.send(event.clone()); }   // 2) потом событие
}

// поток плагина: getActiveFile()
let snap = snapshot.load();                  // дешёвое чтение без блокировок
snap.active_file.clone()
```

Порядок «сначала снимок, потом событие» гарантирует, что обработчик события видит состояние не старее события. Пересчёт метаданных одного файла идёт в фоне (`cx.background_spawn`), а новый снимок переиспользует `Arc` остальных данных, поэтому копирование дешёвое.

**Алгоритмы:**

1. **Открыть вид (`getRightLeaf` + `setViewState`).** Если в правой панели уже есть лист с тем же `view_type`, активировать его. Иначе создать новый лист во вкладках правой панели, сделать активным, открыть панель (`open = true`).
2. **Сохранить.** Любое изменение раскладки увеличивает счётчик поколения и запускает отложенное сохранение на 500 мс. Если за это время пришло новое изменение, старое сохранение отменяется. Запись атомарная: во временный файл, затем `rename`.

```rust
fn schedule_save(&mut self, cx: &mut Context<Self>) {
    self.save_gen += 1;
    let gen = self.save_gen;
    cx.spawn(async move |this, cx| {
        cx.background_executor().timer(Duration::from_millis(500)).await;
        this.update(cx, |this, cx| {
            if this.save_gen == gen { this.write_layout_atomic(cx); }
        }).ok();
    }).detach();
}
```

3. **Восстановить.** Для каждого `LeafState` ищем фабрику в реестре. Нашли: создаём вид и вызываем `setState`. Не нашли: создаём `Placeholder { owner, view_type, state }`. **Состояние заглушки сохраняется при записи раскладки**, поэтому удаление плагина или ошибка загрузки не стирают расположение панели и её данные (идея `InvalidItemView` из Zed).
4. **Плагин загрузился позже.** `on_plugin_loaded(id)`: пройти по заглушкам с `owner == Plugin(id)`, для которых теперь есть фабрика, заменить на реальный вид на том же месте с теми же размерами.
5. **Плагин выгружается.** `on_plugin_unloaded(id)`: запросить `getState()` у каждого его вида (таймаут 200 мс), записать в `LeafState.state`, заменить вид на заглушку.
6. **Порядок кнопок.** В Zed у каждой панели свой `activation_priority`, и дубликаты считаются ошибкой. У нас порядок определяется парой `(priority, plugin_id)`, поэтому он детерминированный и не падает при совпадении.
7. **Размеры.** Размер ограничивается снизу (`min_size`, не меньше толщины ручки изменения размера) и сверху (доля окна). При смене оси (из боковой панели в нижнюю) размер сбрасывается, как это делает Zed.

Вид плагина в GPUI (эскиз): сущность `PluginView` реализует `Render` и рисует дерево из 12.7. Стирание типа через `AnyView`, как у `PanelHandle` и `ItemHandle` в Zed, позволяет хранить встроенные и плагинные виды в одном списке.

**Проверка дерева** (защита от тяжёлых деревьев; значения подбираются по опыту):

```rust
pub fn validate_tree(root: &UiNode) -> Result<(), ApiError> {
    const MAX_DEPTH: usize = 32;
    const MAX_NODES: usize = 2_000;
    const MAX_STR: usize = 64 * 1024;
    let mut nodes = 0;
    let mut ids = HashSet::new();
    fn walk(n: &UiNode, depth: usize, nodes: &mut usize, ids: &mut HashSet<String>) -> Result<(), ApiError> {
        *nodes += 1;
        if depth > MAX_DEPTH || *nodes > MAX_NODES { return Err(ApiError::limit("tree too large")); }
        if let Some(id) = n.id() {
            if !ids.insert(id.to_owned()) { return Err(ApiError::invalid("duplicate id")); }
        }
        if n.max_string_len() > MAX_STR { return Err(ApiError::limit("string too long")); }
        for c in n.children() { walk(c, depth + 1, nodes, ids)?; }
        Ok(())
    }
    walk(root, 0, &mut nodes, &mut ids)
}
```

**Обновление без лишней работы.** GPUI сам перерисовывает вид по `cx.notify()`, поэтому «дифф» нужен в основном, чтобы не гонять и не обрабатывать одинаковые деревья:

1. Плагин вызывает `requestRender()`: ставится флаг. Поток плагина собирает дерево не чаще 30 раз в секунду (объединение нескольких запросов в один).
2. Хост считает хэш дерева (например, `fxhash` от сериализованного JSON) и сравнивает с предыдущим. Совпало: ничего не делать.
3. Не совпало: заменить `Arc<UiNode>` и вызвать `cx.notify()`.

**Состояние полей ввода хранит хост** (иначе ввод лагает):
- Карта `HashMap<(ViewId, NodeId), InputState>`, где `InputState` держит редактор поля.
- При каждом новом дереве: записи, у которых тот же `id` и тот же тип узла, сохраняются, остальные удаляются.
- Значение из `Input.value` применяется, только если оно **отличается от последнего значения, которое хост отправлял плагину**. Иначе плагин, который эхом возвращает ввод, сбивал бы курсор.

**События:** клики и `submit` отправляются сразу, `change` с debounce 150 мс. Каждое событие содержит `view_id`, `node_id` и растущий `seq`. Хост отбрасывает события для узлов, которых уже нет в дереве.

Рендер узла (с использованием реальных токенов темы из `src/theme.rs`):

### 12.8 Модальные окна плагинов

В Zed у рабочей области есть слой `ModalLayer` (его используют, например, `Dock` и `Workspace`). Нужен такой же слой в приложении.

```rust
        let prev_focus = window.focused(cx);          // чтобы вернуть фокус при закрытии
        // заголовок формирует хост, плагин влияет только на хвост
        let full_title = format!("{} — {}", plugin.display_name, title);
        // ...добавить в стек, затянуть фон, поставить фокус на первый интерактивный узел

    }
```

### 12.9 Редактор: версии, транзакции, перенос позиций

Плагин получает результат с задержкой, потому что живёт в другом потоке, а документ за это время мог измениться. Поэтому каждая правка и каждый ответ плагина привязаны к версии документа.

```rust
#[derive(Clone, Copy)]
pub struct Edit { pub start: usize, pub old_len: usize, pub new_len: usize }

#[derive(Clone, Copy, PartialEq)]
pub enum Bias { Left, Right }

/// Сдвигает смещение через последовательность правок.
/// Каждая правка записана относительно документа после предыдущей.
pub fn map_offset(mut pos: usize, edits: &[Edit], bias: Bias) -> usize {
    for e in edits {
        let end = e.start + e.old_len;
        pos = if pos < e.start {
            pos
        } else if pos > end || (pos == end && e.old_len > 0) {
            pos - e.old_len + e.new_len                 // позиция после заменённого куска
        } else {
            match bias { Bias::Left => e.start, Bias::Right => e.start + e.new_len }  // внутри куска или вставка в точке
        };
    }
    pos
}
```

**Декорации:** плагин возвращает диапазоны для версии `V`. Если `V` равна текущей, применяем как есть. Иначе берём `history.edits_since(V)` и переносим каждую границу через `map_offset` (начало с `Bias::Right`, конец с `Bias::Left`). Если `V` старее глубины истории (например, 256 транзакций), ответ отбрасывается, и у плагина запрашивается свежий.

**Транзакции:** `Editor.transact(fn)` собирает все `replaceRange` одного вызова плагина в одну запись истории (один Ctrl+Z). Хост начинает транзакцию перед вызовом команды и заканчивает после обработки её синхронной части. Асинхронные продолжения в транзакцию не входят, это нужно отразить в документации.

**Тесты:** property-тесты (`proptest`) на `map_offset`: монотонность (`a <= b` даёт `map(a) <= map(b)`), вставка в начало сдвигает всё вправо, отмена правки возвращает исходные позиции для позиций вне изменённого куска.

### 12.10 Горячая перезагрузка и выгрузка

Все регистрации плагина записываются как «освобождаемые» объекты. Выгрузка просто выполняет их все.

```rust
type Disposable = Box<dyn FnOnce(&mut PluginHost, &mut Context<PluginHost>) + Send>;

#[derive(Default)]
struct Registrations { disposables: Vec<Disposable> }

impl PluginHost {
    fn register_command(&mut self, plugin: &PluginId, cmd: Command) {
        let id = cmd.id.clone();
        self.commands.insert(id.clone(), cmd);
        self.regs.entry(plugin.clone()).or_default().disposables.push(Box::new(move |host, _| {
            host.commands.remove(&id);
        }));
    }

    pub fn unload(&mut self, plugin: &PluginId, cx: &mut Context<Self>) {
        // 1. вежливая выгрузка: onunload, максимум 500 мс
        if let Some(h) = self.plugins.get(plugin) {
            let _ = h.events_tx.send(HostEvent::Unload);
            h.deadline_ms.store(now_ms() + 500, Ordering::Relaxed);
        }
        // 2. виды превращаются в заглушки с сохранённым состоянием (12.6)
        self.layout_on_plugin_unloaded(plugin, cx);
        // 3. снять все регистрации
        if let Some(regs) = self.regs.remove(plugin) {
            for d in regs.disposables { d(self, cx); }
        }
        // 4. закрыть окна, снять подписки на события, остановить поток
        self.modals.close_all_of(plugin);
        self.plugins.remove(plugin);       // Drop закрывает канал и дожидается потока
    }
}
```

Наблюдение за папкой: крейт `notify` с debounce 200 мс по `main.js` и `manifest.json`. Перезагрузка равна `unload` и `load` для одного плагина. Если новая версия падает при загрузке, плагин остаётся выгруженным, а в консоль плагинов пишется ошибка.

### 12.11 Установка из каталога

```rust
async fn install(entry: &CatalogEntry, http: &HttpClient, plugins_dir: &Path, ask: impl AsyncFn(&Manifest) -> bool) -> Result<()> {
    let base = format!("https://github.com/{}/releases/latest/download", entry.repo);
    let manifest_bytes = http.get_bytes(&format!("{base}/manifest.json")).await?;
    let manifest: Manifest = serde_json::from_slice(&manifest_bytes)?;
    ensure!(manifest.id == entry.id, "manifest id mismatch");
    ensure!(api_supported(&manifest.api_version), "unsupported apiVersion");

    let main_js = http.get_bytes(&format!("{base}/main.js")).await?;
    verify_sha256(&main_js, entry.sha256.get("main.js"))?;     // контрольная сумма из каталога
    verify_sha256(&manifest_bytes, entry.sha256.get("manifest.json"))?;

    // права показываются до установки
    if !ask(&manifest).await { bail!("cancelled"); }

    // атомарная установка: временная папка, затем rename
    let tmp = plugins_dir.join(format!(".{}.tmp", manifest.id));
    let dst = plugins_dir.join(&manifest.id);
    std::fs::create_dir_all(&tmp)?;
    std::fs::write(tmp.join("manifest.json"), &manifest_bytes)?;
    std::fs::write(tmp.join("main.js"), &main_js)?;
    if dst.exists() { std::fs::rename(&dst, plugins_dir.join(format!(".{}.old", manifest.id)))?; }
    std::fs::rename(&tmp, &dst)?;
    Ok(())
}

fn verify_sha256(bytes: &[u8], expected_hex: Option<&String>) -> Result<()> {
    use sha2::{Digest, Sha256};
    let Some(expected) = expected_hex else { bail!("catalog entry has no checksum") };
    let got = hex::encode(Sha256::digest(bytes));
    ensure!(got.eq_ignore_ascii_case(expected), "checksum mismatch");
    Ok(())
}
```

Обновление: загрузить новый `manifest.json`, сравнить через `permissions_expanded` (12.3). Если права расширились, снова показать диалог. Если пользователь отказался, остаётся старая версия. Старая папка `.old` удаляется после успешной загрузки новой версии. Список `blocklist.json` проверяется при каждом запуске и после каждой загрузки каталога.

### 12.14 Проверка плагинов: крейт `plugin-verify` (общая часть)

Схема и политика описаны в core §6.1. Здесь общий код. Проверка бандла (`static_check`) и пробный запуск (`dry_run`) зависят от формата бандла и реализуются в `RuntimeVerifier`: для JS это JS §6, для WASM это WASM §6.

```rust
// plugin-verify (используется приложением, CLI SDK и CI каталога)
#[derive(Serialize, Deserialize, Clone)]
pub struct Finding { pub code: String, pub message: String, pub line: Option<u32> }

#[derive(Serialize, Deserialize, Clone, Default)]
pub struct VerifyReport {
    pub ok: bool,
    pub errors: Vec<Finding>,
    pub warnings: Vec<Finding>,
    pub bundle_sha256: String,
    pub host_version: String,
    pub stats: DryRunStats,        // время вызовов, пик памяти, число обращений к API
}

impl VerifyReport {
    pub fn error(&mut self, code: &str, msg: impl ToString) {
        self.errors.push(Finding { code: code.into(), message: msg.to_string(), line: None });
    }
    pub fn warn(&mut self, code: &str, msg: impl ToString) {
        self.warnings.push(Finding { code: code.into(), message: msg.to_string(), line: None });
    }
    pub fn finish(mut self) -> Self { self.ok = self.errors.is_empty(); self }
}

pub struct Limits {
    pub memory: usize,             // память пробного запуска
    pub onload_ms: u64,            // 500
    pub call_ms: u64,              // 100
    pub max_registrations: usize,  // 50 на тип
    pub max_bundle: usize,         // размер бандла
}
impl Limits {
    pub fn js()   -> Self { Self { memory: 32 << 20, onload_ms: 500, call_ms: 100, max_registrations: 50, max_bundle: 5 << 20 } }
    pub fn wasm() -> Self { Self { memory: 64 << 20, onload_ms: 500, call_ms: 100, max_registrations: 50, max_bundle: 20 << 20 } }
}

/// То, что зависит от формата бандла.
pub trait RuntimeVerifier {
    /// Статическая проверка без выполнения кода плагина.
    fn static_check(&self, manifest: &Manifest, bundle: &[u8], r: &mut VerifyReport);
    /// Пробный запуск в одноразовой песочнице на моковом приложении.
    fn dry_run(&self, manifest: &Manifest, bundle: &[u8], host: Arc<MockHost>, lim: &Limits, r: &mut VerifyReport);
}

pub fn verify(rt: &dyn RuntimeVerifier, manifest: &Manifest, bundle: &[u8], limits: &Limits) -> VerifyReport {
    let mut r = VerifyReport::default();
    r.bundle_sha256 = sha256_hex(bundle);
    r.host_version = HOST_VERSION.into();

    check_manifest(manifest, &mut r);                       // схема, id, runtime, apiVersion, права
    if bundle.len() > limits.max_bundle { r.error("bundle.too_large", "bundle exceeds the size limit"); }
    if !r.errors.is_empty() { return r.finish(); }          // дальше смысла нет

    rt.static_check(manifest, bundle, &mut r);
    if !r.errors.is_empty() { return r.finish(); }

    let mock = Arc::new(MockHost::new());
    rt.dry_run(manifest, bundle, mock.clone(), limits, &mut r);

    // общая проверка утечек: после onunload все регистрации должны быть сняты (core §12.10)
    let leaks = mock.run_disposables_and_count_left();
    if leaks > 0 { r.error("unload.leak", format!("{leaks} registrations left after unload")); }
    r.finish()
}
```

**Один слой привязок для боевого и пробного запуска.** Рантаймы отправляют запросы плагина не прямо в канал, а в `HostApi`. В бою это мост, в проверке это мок. Ответ в обоих случаях возвращается одинаково: событием `HostEvent::Response` через `PluginRuntime::send_event`. Так пробный запуск выполняет тот же код привязок, что и боевой, а подменяется только «приложение».

```rust
pub trait HostApi: Send + Sync {
    /// Принять запрос плагина. Ответ придёт как HostEvent::Response (в бою позже, в MockHost сразу).
    fn submit(&self, call: ApiCall);
}

/// Боевой режим: запрос уходит в мост (core §12.2).
pub struct BridgeHost { api_tx: UnboundedSender<ApiCall> }
impl HostApi for BridgeHost {
    fn submit(&self, call: ApiCall) { let _ = self.api_tx.unbounded_send(call); }
}

/// Пробный режим: ничего не трогает, всё записывает и отвечает сразу.
pub struct MockHost {
    log: Mutex<Vec<ApiRequest>>,
    sample_vault: Vec<(String, String)>,                     // 3 типовые заметки
    registrations: Mutex<Registrations>,                     // то же, что в core §12.10
    respond: Mutex<Option<Box<dyn Fn(HostEvent) + Send>>>,   // ставит песочница рантайма
}

impl HostApi for MockHost {
    fn submit(&self, call: ApiCall) {
        self.log.lock().unwrap().push(call.request.clone());
        let result: Result<serde_json::Value, (&str, &str)> = match &call.request {
            ApiRequest::VaultRead { path } => self.sample_read(path),
            ApiRequest::VaultModify { .. }  => Ok(serde_json::Value::Null),        // запись никуда не уходит
            ApiRequest::Http { .. }         => Err(("offline", "network disabled in dry-run")),
            _ => Ok(serde_json::Value::Null),
        };
        if let Some(respond) = &*self.respond.lock().unwrap() {
            respond(HostEvent::response(call.id, result));
        }
    }
}
```

```rust
fn load_guarded(&mut self, id: &PluginId, cx: &mut Context<Self>) {
    let marker = self.data_dir.join(format!("loading-{id}"));     // в папке данных приложения, не в vault
    if marker.exists() {
        self.disable(id, DisableReason::CrashedOnLastStart);      // уведомление пользователю
        let _ = std::fs::remove_file(&marker);                    // дальше пользователь включит вручную
        return;
    }
    let _ = std::fs::write(&marker, b"");

    if self.needs_verify(id, &self.bundle_sha(id)) {
        let report = self.verify_in_background(id);               // plugin-verify, фоновая задача
        self.store_cache(id, &report);
        if !report.ok { self.reject(id, report); let _ = std::fs::remove_file(&marker); return; }
    }

    self.load(id, cx);

    // маркер снимается, если приложение прожило с плагином 10 секунд
    let marker2 = marker.clone();
    cx.spawn(async move |_this, cx| {
        cx.background_executor().timer(Duration::from_secs(10)).await;
        let _ = std::fs::remove_file(marker2);
    }).detach();
}
```
