# Поиск: десктопный Vibecodium vs Obsidian vs мобильный Vibecodium

Сравнение трёх реализаций:

- **Vibecodium desktop** (`aquilum-gpui`) — глобальный поиск по vault и
  in-editor find bar;
- **Obsidian Mobile 1.15.0** — in-page search в reading и source/live-preview;
- **Vibecodium mobile** (`vibecodium-mobile`) — глобальный поиск по vault;
  in-page поиска пока нет.

Главный вывод: **десктопный Vibecodium лучше по алгоритмам, индексации и
устойчивости к большим документам**, а **Obsidian лучше по охвату режимов и
мобильному UX**. Мобильный Vibecodium уже догнал Obsidian по базовому виду
группированной выдачи, но его backend проще десктопного.

## 1. Что есть на десктопе

### 1.1. Глобальный поиск по vault

Файлы:

- `src/search/worker.rs` — фоновый worker;
- `src/search/index.rs`, `bm25.rs`, `query.rs`, `tokenize.rs` — индекс и
  ранжирование;
- `src/search/cache.rs` — LRU-кэш тел файлов;
- `src/search/locate.rs` — поиск страницы для больших файлов;
- `src/views/sidebar/search_panel.rs` — UI панели;
- `src/views/goto_search.rs`, `goto_search/query.rs` — общий движок выдачи.

Что реализовано:

- постоянный индекс на workspace, с сохранением на диск и загрузкой при
  открытии vault;
- индекс наполняется builder-ом в фоне, поиск работает уже по частичному
  индексу, недостающие файлы добираются позже;
- BM25F-ранжирование; отдельные операторы `path:`, `file:`, `tag:`, `line:`,
  `section:`;
- переключатель `Aa` (case-sensitive) и fallback на линейный scan для
  case-sensitive запросов, потому что индекс хранит folded-термы;
- worker с отменой устаревших запросов, sequence numbers и приоритетом поиска
  над построением индекса;
- LRU-кэш тел файлов на 64 МБ: повторный ввод не перечитывает диск;
- файлы до 512 КБ читаются целиком, более крупные — через первый мегабайт;
  для больших файлов индекс знает страницы с термином, и `locate` проверяет
  только нужные страницы;
- лимиты: до 2000 просматриваемых файлов и 50 результатов на запрос;
- выдача: группы по файлам, сворачивание, подсвеченные сниппеты, количество
  совпадений, история запросов, скроллбар.

Это заметно мощнее текущего мобильного поиска: там есть индекс и snapshot, но
нет отдельного worker-а, LRU-кэша тел, операторов, case-toggle, истории и
такой же работы с большими файлами.

### 1.2. In-editor find bar (Ctrl+F)

Файлы:

- `src/views/find_bar.rs` — состояние бара;
- `src/views/find_bar/scan.rs` — алгоритм сканирования;
- `src/views/app_view/find.rs` — жизненный цикл, навигация, replace;
- `src/views/app_view.rs:784` — отрисовка.

Что реализовано:

- панель между заголовком заметки и телом редактора;
- поле запроса с иконкой поиска, счётчиком `current/total`, кнопками `Aa`,
  whole word, очисткой и стрелками;
- отдельная строка replace с replace/replace-all и процентом выполнения;
- сканирование **чанками по 256 КБ** прямо по rope, без копирования всего
  документа в строку;
- перекрытие окна на длину запроса, чтобы совпадение на границе чанка не
  терялось и не находилось дважды;
- лимит 19 999 совпадений; при достижении лимита счётчик получает `+`;
- отмена между чанками;
- версия документа: результаты старой версии выбрасываются, если документ
  изменился во время сканирования;
- pending-состояния: Enter/Replace/Mark all, нажатые во время сканирования,
  применяются к свежему результату;
- replace-all собирает новый текст потоково, показывает прогресс и может быть
  отменён;
- «Mark all» помечает строки, затронутые запросом;
- навигация не двигает каретку редактора, пока пользователь сам не выберет
  переход;
- горячие клавиши: Ctrl+F, Enter/Shift+Enter, Escape.

Стоимость: `O(n)` по документу, память ограничена окном сканирования плюс
списком диапазонов, а не размером документа. Это очень хорошая реализация для
больших файлов.

## 2. Что есть в Obsidian Mobile

Подробный разбор: `aquilum-gpui/TODO/obsidian-mobile-inpage-search.md`.

В Obsidian две реализации in-page поиска:

### Reading / preview

- проходит по тексту отрендеренных DOM-секций;
- lower-case + `indexOf`, собирает все вхождения;
- рисует overlay-div поверх текста;
- счётчик точный;
- активное совпадение центрируется через `scrollIntoView(block:center)`;
- replace недоступен.

Минусы: lower-case копия текста, DOM Range/client rects и overlay для всех
видимых совпадений; на заметке с тысячами совпадений дорого.

### Source / live-preview

- CodeMirror `SearchCursor`: потоковый literal substring;
- case-insensitive всегда, без `Aa`/whole-word;
- `findNext`/`findPrevious` с заворотом, `findAll`, replace/replace-all;
- счётчик `current/total` считается проходом от начала до текущего совпадения,
  ограничен 9999;
- подсветка текущего совпадения, «Find all» — по кнопке;
- replace только в source-режиме;
- панель сверху заметки, на телефоне во всю ширину.

Obsidian выигрывает в другом: **поиск работает и в reading, и в source**, у него
очень аккуратная мобильная панель, prefill из выделения и центрирование
активного совпадения. Но по алгоритму и возможностям замены он слабее
десктопного Vibecodium.

## 3. Прямое сравнение

| Критерий | Vibecodium desktop | Obsidian Mobile | Vibecodium mobile |
|---|---|---|---|
| Глобальный поиск по vault | Индекс + worker + cache + операторы | Есть, но без такого индекса/воркера | Индекс-snapshot + простой coroutine |
| In-page search | Есть, очень развитый | Есть в reading и source | Пока нет |
| Режимы in-page | Редактор (source/live) | Reading + source/live | — |
| Алгоритм in-page | Чанки rope, bounded memory | DOM scan / CM SearchCursor | — |
| Отмена | Между чанками | Нет отдельной отмены | — |
| Лимит совпадений | 19 999 + `+` | 9 999 в source, без лимита в reading | — |
| Case / whole word | Да | Нет | Нет |
| Replace | Да, с прогрессом и отменой | Только source | — |
| Mark all | Да | Нет | — |
| Счётчик | Точный до лимита | Точный в reading, до 9999 в source | По диапазонам |
| Группировка по файлам | Да | Глобальный поиск — да | Да |
| Сворачивание файлов | Да | Да | Да |
| Скроллбар | Да | Да | Да |
| Операторы | `path:`, `file:`, `tag:`, `line:`, `section:` | Глобальный поиск — да | Нет |
| История запросов | Да | Нет в in-page | Нет |
| Мобильный UX | Нет (десктоп) | Лучший | Хороший для глобального |

## 4. Где что реализовано лучше

### Десктопный Vibecodium

Лучше:

- глобальный поиск: индекс, worker, LRU-кэш, операторы, отмена, прогресс
  построения, устойчивость к большим vault;
- in-page поиск: потоковое сканирование rope, bounded memory, отмена,
  версионирование, case/whole-word, replace-all с прогрессом, mark all;
- работа с очень большими файлами: страницы индекса + `locate`, ограниченный
  head для oversize-файлов.

Слабее:

- нет мобильного touched-интерфейса;
- in-page search не покрывает отдельный reading-режим (в десктопе его роль
  выполняет редактор/preview, но отдельного DOM-поиска как в Obsidian нет);
- глобальная выдача ограничена 50 файлами, хотя это осознанный компромисс.

### Obsidian Mobile

Лучше:

- in-page поиск доступен и в reading, и в source/live;
- мобильная панель: full-width, safe-area, кнопки, скрытие клавиатуры;
- prefill запроса из выделения;
- визуально аккуратная подсветка overlay-слоями в reading;
- центрирование активного совпадения.

Слабее:

- нет индекса и воркера для глобального поиска (линейный обход файлов);
- in-page source: нет case/whole-word, счётчик ограничен 9999, нет прогресса
  replace-all/mark all;
- reading: lower-case копия текста и DOM-overlay на каждое совпадение;
- replace только в source.

### Vibecodium mobile

Лучше:

- теперь есть группировка по файлам, бейджи, сворачивание, скроллбар и переход
  к совпадению с центрированием;
- проще и легче по коду, чем desktop/worker-инфраструктура.

Слабее:

- backend глобального поиска проще: нет отдельного worker-а, LRU-кэша,
  операторов, case-toggle, истории;
- in-page поиска пока нет;
- лимит 200 файлов и 200 совпадений на файл — эвристика, а не индексная
  выдача.

## 5. Что я бы взял из десктопа для мобильного

1. **In-page поиск** делать по модели `find_bar`:
   - тот же чанковый/rope-подход или эквивалентный потоковый скан;
   - отмена между чанками;
   - версия документа, чтобы старые диапазоны не применялись после правки;
   - case/whole-word;
   - replace-all с прогрессом;
   - счётчик с лимитом и `+`.
2. **Глобальный поиск** постепенно приблизить к desktop:
   - вынести индекс/скан в отдельный worker;
   - добавить LRU-кэш тел;
   - добавить операторы и case-toggle;
   - сохранить текущую Obsidian-подобную группировку/сворачивание.
3. **Из Obsidian** оставить:
   - мобильную панель сверху, prefill из выделения;
   - центрирование активного совпадения;
   - два режима, если на мобильном появится отдельный reading-view.

Итог: **алгоритмически и по возможностям замены/больших файлов лучше
десктопный Vibecodium; по мобильному UX и охвату режимов — Obsidian; мобильный
Vibecodium сейчас лучший компромисс по UI, но его поисковый backend ещё проще
десктопного.**
