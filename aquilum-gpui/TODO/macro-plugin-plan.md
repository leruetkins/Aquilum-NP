# План: встроенный плагин макросов (аналог TextPad-макросов + QuickAdd)

Цель: дать пользователю запись/повтор правок, массовую regex-замену и скриптовые макросы. Реализуем как **bundled-плагин на публичном plugin API**, а в ядро выносим только механизмы, без которых плагин невозможен.

Принцип: если фичу нельзя написать через публичный API, расширяем API, а не вшиваем фичу в ядро.

---

## 0. Предварительный аудит существующей прослойки плагинов

Перед стартом проверить в текущем коде (ответы определяют объём этапов 1-2):

| Вопрос | Что нужно |

| Есть ли undo-группы / транзакции? | Если нет, этап 1b обязателен |
| Может ли плагин подписаться на события редактора? | Нужен `EditorEvent` stream |

Результат аудита: короткая заметка «что уже есть / чего не хватает» перед этапом 1.

## 1. Ядро: шина действий редактора

### 1a. `EditorAction`

Все изменения редактора выражаются данными. Это основа рекордера.

```rust
#[derive(Clone, Debug, serde::Serialize, serde::Deserialize, PartialEq)]
#[serde(tag = "type")]
pub enum EditorAction {
    // Текст
    InsertText { text: String },
    DeleteBackward { unit: Unit, count: u32 },
    DeleteForward { unit: Unit, count: u32 },
    // Курсор и выделение
    MoveCursor { motion: Motion, extend_selection: bool },
    SelectAll,
    SelectLine,
    // Буфер обмена
    Cut,
    Copy,
    Paste,
    // Поиск
    Find { query: String, regex: bool, case_sensitive: bool, direction: Direction },
    ReplaceCurrent { replacement: String },
    // Строки
    DuplicateLine,
    MoveLine { direction: Direction },
    // Прочее
    Indent,
    Outdent,
}

#[derive(Clone, Copy, Debug, serde::Serialize, serde::Deserialize, PartialEq)]
pub enum Unit { Char, Word, Line }

#[derive(Clone, Copy, Debug, serde::Serialize, serde::Deserialize, PartialEq)]
pub enum Motion {
    Left, Right, Up, Down,
    WordLeft, WordRight,
    LineStart, LineEnd,
    DocStart, DocEnd,
    NextMatch, PrevMatch,
}

#[derive(Clone, Copy, Debug, serde::Serialize, serde::Deserialize, PartialEq)]
pub enum Direction { Forward, Backward }
```

Правила:
- Клавиатурный ввод, меню и хоткеи транслируются в `EditorAction`, а затем исполняются единым `apply_action(&mut DocumentBuffer, &mut Cursor, EditorAction)`.
- `apply_action` не зависит от GPUI (чистая логика на `ropey`), поэтому тестируется без UI.
- Действие возвращает `ActionOutcome { changed: bool, error: Option<ActionError> }`, чтобы цикл «повторять до конца» мог остановиться, когда `Find` не нашёл совпадений.

### 1b. Undo-группы

```rust
impl DocumentBuffer {
    pub fn begin_transaction(&mut self) -> TransactionId;
    pub fn end_transaction(&mut self, id: TransactionId);
}
```

- Всё между `begin` и `end` откатывается одним Ctrl+Z.
- Вложенные транзакции склеиваются во внешнюю.
- Если макрос упал на середине, транзакция закрывается, а изменения остаются откатываемыми одной операцией.

### 1c. Поток событий

```rust
pub enum EditorEvent {
    ActionApplied { doc: DocId, action: EditorAction },
    ActiveDocChanged { doc: Option<DocId> },
}
```

- Рекордер подписывается на `ActionApplied`.
- Во время replay события помечаются `source: ActionSource::Macro`, чтобы рекордер не записал сам себя.

### Тесты этапа 1 (без GPUI)

- `apply_action` на каждый вариант `EditorAction` (юникод, границы файла, пустой документ).
- Транзакция: N действий, один undo возвращает исходный текст.
- Вложенные транзакции.
- Сериализация `EditorAction` в JSON и обратно (стабильный формат, он станет форматом файла макроса).

## 2. Ядро: расширение plugin API

Добавить в существующую прослойку (названия подогнать под текущие):

```rust
pub trait EditorApi {
    fn active_doc(&self) -> Option<DocId>;
    fn run(&mut self, action: EditorAction) -> ActionOutcome;
    fn transaction<R>(&mut self, f: impl FnOnce(&mut Self) -> R) -> R;
    fn get_text(&self, doc: DocId) -> String;
    fn get_line(&self, doc: DocId, line: usize) -> Option<String>;
    fn line_count(&self, doc: DocId) -> usize;
    fn get_selection(&self, doc: DocId) -> Selection;
    fn set_selection(&mut self, doc: DocId, sel: Selection);
    fn replace_range(&mut self, doc: DocId, range: Range<usize>, text: &str);
    fn subscribe(&mut self, handler: Box<dyn Fn(&EditorEvent)>) -> Subscription;
}
```

Дополнительно:
- **Динамические команды**: `add_command` / `remove_command` во время работы (макрос появляется в палитре команд сразу после сохранения).
- **Динамические хоткеи** для таких команд, с проверкой конфликтов.
- **Bundled-плагины**: список встроенных плагинов, включённых по умолчанию, отключаемых в настройках, не удаляемых.
- **Статус-бар**: слот, в который плагин может положить индикатор (например, красная точка «REC» и счётчик шагов).
- **Диалоги ввода**: `prompt(text) -> Option<String>`, `Notice` (у вас уже есть).

## 4. Рекордер и воспроизведение

### Модель

```rust
#[derive(Serialize, Deserialize)]
pub struct Macro {
    pub id: String,            // slug
    pub name: String,
    pub hotkey: Option<String>,
    pub steps: Vec<EditorAction>,
    pub created_at: i64,
}

pub enum PlayMode {
    Once,
    Times(u32),
    UntilFailure,   // до первой неудачи, например Find не нашёл совпадение
    UntilEndOfDoc,  // пока курсор не достиг конца документа
}
```

### Рекордер

- Команды: `Macro: start recording`, `Macro: stop recording`, `Macro: save last recording`.
- Состояние: `Idle | Recording { steps }`.
- Пока идёт запись, подписка на `ActionApplied`, `source == User`.
- Оптимизация при записи: подряд идущие `InsertText` склеиваются в один шаг.
- Не записывать: действия плагинов, смену активной вкладки (если пользователь переключил документ во время записи, показать предупреждение и остановить запись).
- Хранить «последнюю запись» всегда, даже без явного сохранения (аналог безымянного макроса TextPad), и команду `Macro: replay last`.

### Воспроизведение

```rust
pub fn play(editor: &mut impl EditorApi, m: &Macro, mode: PlayMode) -> PlayReport {
    editor.transaction(|ed| {
        let mut iterations = 0;
        loop {
            for step in &m.steps {
                let out = ed.run(step.clone());
                if out.error.is_some() { return PlayReport::failed(iterations, out); }
            }
            iterations += 1;
            if mode.should_stop(iterations, ed) { break; }
            if iterations >= HARD_LIMIT { break; } // защита от бесконечного цикла
        }
        PlayReport::ok(iterations)
    })
}
```

- Весь прогон в одной транзакции: один Ctrl+Z отменяет всё.
- `HARD_LIMIT` (например, 100 000 итераций) и проверка «текст не менялся и курсор не двигался за итерацию» против зависания в `UntilFailure`.
- Отмена воспроизведения по Esc.
- Для больших документов: не перерисовывать UI на каждом шаге, а обновить один раз по завершении.

### Хранение

- `macros.json` в папке данных плагина: `Vec<Macro>`.
- Каждый макрос регистрируется как команда `Macro: <name>` с его хоткеем.
- Команды управления: переименовать, удалить, назначить хоткей, экспорт/импорт одного макроса в `.json`.

### Тесты

- Запись последовательности, склейка `InsertText`, воспроизведение даёт тот же результат.
- `UntilFailure` останавливается на `Find` без совпадений.
- `HARD_LIMIT` срабатывает.
- Один undo откатывает весь прогон.
- Рекордер не записывает действия, исходящие из воспроизведения.

## 5. Regex-замена

Самый частый сценарий «массовых правок», делаем отдельным этапом, не зависящим от скриптов.

- Область: текущий файл / выделение / vault / выбранные папки.
- Опции: regex, регистр, целое слово, многострочный режим, группы захвата в замене (`$1`).
- **Предпросмотр**: список совпадений «файл: строка: было → станет», с галочками по каждому.
- Применение: одна транзакция на файл; для vault дополнительно история «что изменено» и возможность отката по файлам.
- Сохраняемые наборы правил: цепочка из нескольких замен, запускаемая как макрос (`Macro::Steps` может содержать шаг `RegexReplace`).
- Крейт `regex` (без look-around). Если понадобятся look-around и backreferences, подключить `fancy-regex` как опцию, с пометкой в UI.

Тесты: юникод, пустые совпадения, перекрытия, многострочные, replace с группами, предпросмотр совпадает с результатом.

## 6. Скриптовые макросы

### Выбор движка (решить перед этапом)

| Движок | Когда выбирать |
|---|---|
| **rquickjs (JS)** | API зеркалит Obsidian, пользователи переносят знания и сниппеты |
| **Rhai** | Нужна простая и безопасная интеграция, чисто Rust |
| **mlua (Lua)** | Нужны скорость и маленький размер, не страшна C-зависимость |
| **WASM** | Нужна полная изоляция и любой язык для авторов (самый дорогой вариант) |

Движок прячем за трейтом, чтобы его можно было заменить:

```rust
pub trait ScriptEngine {
    fn run(&mut self, source: &str, ctx: ScriptContext) -> Result<ScriptValue, ScriptError>;
}
```

### Что видит скрипт

```js
// пример на JS-синтаксисе (для Rhai/Lua аналогично)
const lines = editor.lines();
editor.transaction(() => {
  for (let i = 0; i < lines.length; i++) {
    const m = lines[i].match(/ID:\s*(\d+)/);
    if (m) editor.setLine(i, `[${m[1]}] ` + lines[i]);
  }
});
new Notice("Готово");
```

Объекты:
- `editor`: `lines()`, `getLine(i)`, `setLine(i, s)`, `replaceRange`, `getSelection`, `setSelection`, `run(action)`, `transaction(fn)`.
- `vault`: `read(path)`, `write(path, text)`, `list(folder)`, `create`, `rename` (права проверяются песочницей).
- `ui`: `Notice`, `prompt`, `pick(list)`.
- `params`: значения, переданные макросу из UI/другого макроса.

### Песочница и безопасность

- Лимит времени и памяти на запуск (прерывание по таймеру).
- Доступ к файлам только внутри vault.
- Запрет сети и процессов по умолчанию; включается явным разрешением в настройках плагина.
- Ошибки скрипта показываются в Notice и в панели вывода со строкой и текстом ошибки; транзакция откатывается.

### Расположение

- Папка `macros/*.js` (или `.rhai`) в конфиг-каталоге vault.
- Файловый вотчер перерегистрирует команды при изменении скриптов (горячая перезагрузка).
- Заголовок скрипта (комментарий или frontmatter) задаёт имя команды, хоткей и параметры.

### Тесты

- Скрипт-пример выше изменяет текст как ожидается.
- Бесконечный цикл прерывается по таймауту.
- Доступ к файлу вне vault отклоняется.
- Ошибка в середине скрипта откатывает правки.

## 7. UI

- **Статус-бар**: индикатор записи (REC + число шагов), кнопка Stop.
- **Панель/окно макросов** (отдельное окно GPUI, как каталог плагинов и настройки): список макросов, Play / Play N раз / Play до конца, переименование, хоткей, удаление, просмотр шагов (read-only, на старте).
- **Окно regex-замены**: поля поиска и замены, опции, область, предпросмотр с галочками, кнопка «Применить».
- **Палитра команд**: все макросы и скрипты доступны как `Macro: <name>`.
- **Настройки плагина**: лимиты воспроизведения, разрешения скриптов, папка скриптов.

## 8. Порядок работ и критерии готовности

| Этап | Содержание | Готово, когда |
|---|---|---|
| 0 | Аудит прослойки плагинов | Есть список «есть / нет» |
| 1 | `EditorAction`, `apply_action`, undo-группы, `EditorEvent` | Тесты этапа 1 зелёные, клавиатура идёт через шину |
| 2 | Расширение plugin API, bundled-плагины, динамические команды | Плагин-пустышка регистрирует команду и подписывается на события |
| 3 | Скелет плагина `macros`, модель и хранилище | Макрос вручную добавленный в JSON появляется командой |
| 4 | Рекордер и воспроизведение | Записал, сохранил, повторил N раз, один Ctrl+Z откатил |
| 5 | Regex-замена с предпросмотром | Замена по vault с откатом |
| 6 | Скриптовый движок и API | Пример со скриптом работает, таймаут и песочница проверены |
| 7 | UI: окно макросов, индикатор, окно regex | Весь сценарий без ручного редактирования JSON |

Первый выпуск можно ограничить этапами 1-4 и 5: рекордер плюс regex дают основную пользу TextPad. Скрипты (этап 6) идут следующим релизом.

## 9. Риски и открытые вопросы

- **Не все действия сериализуются**: действия, зависящие от состояния UI (например, клик мышью по позиции), в макросы не попадают; рекордер показывает предупреждение «шаг не записан».
- **Макрос зависит от контекста**: `Find` в разных документах даёт разный результат. Поэтому предусмотрены `UntilFailure` и явный отчёт `PlayReport`.
- **Хоткеи**: конфликты с пользовательскими и системными, нужна проверка при назначении.
- **Движок скриптов**: выбор влияет на API и размер бинарника. Решение нужно принять до этапа 6.
- **Формат макроса**: после публикации менять его трудно, поэтому в файл сразу добавить поле `version`.
- **Мультиоконность и сплиты**: воспроизведение работает на активном документе активного сплита; если тот же файл открыт в нескольких сплитах, правки идут через общий `DocumentRegistry`, остальные сплиты обновляются по вашему обычному механизму.
