# Задание: инлайн-редактирование таблиц в живом просмотре markdown (GPUI)

## Цель

Таблицы GFM в редакторе рисуются сеткой, а редактируются прямо в ней. Буфер остаётся единственным источником правды: сетка только показывает текст, курсор и выделение живут в символах исходной строки. Отдельных мини-редакторов на ячейку нет.

Дополнительно: у каждой таблицы есть переключатель «исходник», который на время показывает её обычным текстом с `|` и разделителем.

## Контекст и файлы

- `markdown.rs` — живой путь: построчная модель (`classify_line`, `build_visual_rows`, `VisualRowHeightIndex`, `row_painted_text`, `PaintedRow.line_chars`). Все колонки — индексы символов (chars) внутри строки.
- `markdown_doc.rs` — блочная модель на `pulldown_cmark` (`ENABLE_TABLES` включён). Какой путь реально рисует, уточнить в коде; задание рассчитано на построчный.
- `views/app_view.rs` — рендер строки (`render_live_styled_row` должен совпадать с `row_painted_text`) и обработка клавиш.
- `table.rs` (приложен, 18 тестов проходят, `pulldown-cmark 0.13`) — чистая модель таблицы без UI и состояния. Не переписывать, расширять только по необходимости и с тестами.

### API `table.rs`

- Блоки: `find_tables(lines) -> Vec<TableBlock>`, `table_at(lines, line)` (парсит только абзац вокруг строки; не знает про кодовые блоки, результат фильтровать по `analyze_code_blocks`). `TableBlock { first_line, last_line, aligns }`, `row_of_line`, `line_of_row`, `sep_line`, `contains`. Таблицы внутри цитат и списков не находятся.
- Ячейки: `split_row(line) -> Vec<Cell { outer, content }>` в char-индексах, `\|` не разделитель; `cell_index_at(cells, col)`.
- Модель: `TableModel::parse / serialize(pad, width) / insert_row / delete_row / insert_col / delete_col / move_col / set_align / sort_by_col / from_tsv / to_tsv`.
- Правки: `LineEdit { first_line, old_line_count, new_lines }`, `rewrite(block, model, pad, width)`.
- Клавиши: `tab(...) / enter(...) -> Option<Nav { To, AppendRow, Exit }>`, `nav_cursor(block, lines, row, cell, Place)`.
- Защита: `guard_edit(block, line_idx, line, sel) -> EditGuard { Allow, Deny }`, `sanitize_cell_input`.

## Что сделать

### 1. Индекс таблиц (архитектура `aquilum-app`: без `pulldown_cmark`, потоковый автомат)

В отличие от первоначального варианта на `pulldown_cmark`, для исключения деградации скорости на больших файлах со множеством таблиц используется легковесный однопроходный конечный автомат строк из `aquilum-app`:

- **Быстрое определение строк (`syntax.rs`)**:
  - `is_row(line)`: проверка наличия разделителя `|` и разбиение на ячейки без тяжелого парсера.
  - `is_separator(line)`: строка-разделитель, ячейки которой содержат только дефисы `-` и опциональные двоеточия `:`.
  - `align_of(cell)`: выравнивание (`Left`, `Center`, `Right`) по положению двоеточий в разделителе.
- **Определение границ таблицы**:
  - Таблица начинается на строке $L$, если `is_row(L)` и `is_separator(L + 1)`.
  - Таблица продолжается, пока строки удовлетворяют `is_row(i)`, и завершается перед первой пустой строкой, строкой без `|` или концом файла.
- **Сквозная скорость $O(N)$**:
  - Никаких вызовов тяжелого `pulldown_cmark::Parser` для индексации.
  - Первичное сканирование 100 000 строк документа занимает единицы миллисекунд (скорость чтения памяти).
  - При редактировании (`apply_edit`) индекс обновляется за $O(1)$: сдвиг смещений блоков выше строки правки и локальный перескан только одного абзаца.

```rust
pub struct TableIndex {
    rev: Option<u64>,
    blocks: Vec<TableBlock>,
}

impl TableIndex {
    pub fn scan_rope(&mut self, rev: u64, rope: &crop::Rope);
    pub fn apply_edit(&mut self, rev: u64, edit_line: usize, line_diff: isize, rope: &crop::Rope);
    pub fn at(&self, line: usize) -> Option<&TableBlock> {
        let i = self.blocks.partition_point(|t| t.last_line < line);
        self.blocks.get(i).filter(|t| t.first_line <= line)
    }
}
```

### 1.1. Ленивая модель и компоновка ячеек (принцип Embeds из `aquilum-app`)

- При открытии документа детальные модели таблиц (`TableModel`) и их геометрия **не вычисляются** для всего файла. В `TableIndex` хранятся только легкие дескрипторы `TableBlock { first_line, last_line, col_count, aligns }`.
- `TableModel::parse` и измерение колонок (`compute_table_layout`) вызываются **строго лениво (on-demand)** — исключительно для тех таблиц, которые в данный момент входят в видимое окно просмотра (`visible_range`).
- Раскладка каждой видимой таблицы кешируется по ключу `(first_line, hash(содержимое))`. Таблицы вне экрана не потребляют ресурсы CPU и шрифтового движка.

### 2. Режим «исходник» (переключатель на одну таблицу)

Состояние редактора: `raw_table: bool`. Единственная точка принятия решения:

```rust
fn grid_table_at(&self, line: usize) -> Option<&TableBlock> {
    let t = self.tables.at(line)?;
    if self.raw_table && t.contains(self.cursor_line) { None } else { Some(t) }
}
```

Везде, где нужен ответ «рисовать ли эту строку сеткой» (`build_visual_rows`, раскладка, Tab/Enter, `guard_edit`), использовать `grid_table_at`, а не `tables.at`.

Поведение:
- Включение: кнопка `</>` над правым краем таблицы или `Ctrl+/`. Тем же способом выключается. Курсор остаётся на том же символе.
- Пока режим включён и курсор в таблице: строки таблицы рисуются как обычный текст (видны `|` и `|---|`), перенос по словам снова работает, Tab и Enter обычные, `guard_edit` не применяется, правки свободные.
- Выход курсора из таблицы (`tables.at(cursor_line).is_none()` или курсор вне блока) сбрасывает `raw_table = false`, таблица снова сеткой.
- Сломанная правкой таблица перестаёт находиться `find_tables` и остаётся текстом, режим тоже сбрасывается.
- После переключения пересчитать высоты строк таблицы в `VisualRowHeightIndex`, иначе прокрутка сдвинется.

Кнопка (макеты 4 и 5 на холсте):
- Таблетка высотой 30 px, скругление 15 px: глиф `</>` моноширинным шрифтом (акцентный `#7aa2ff`) и подпись «Исходник». Видна только когда курсор в таблице или при наведении на таблицу.
- Состояния: обычная (рамка нейтральная, фон `#2a2d35`), нажатая (рамка акцентная `#7aa2ff`, фон акцента 18%, `aria-pressed = true`, `aria-label = "Вернуть сетку"`), наведение с подсказкой «Исходник таблицы Ctrl+/».
- Положение: справа от таблицы на уровне шапки (отступ 28 px), не перекрывает кнопки «+» у краёв.
- Опционально: настройка «Таблицы: всегда сетка / сетка, но исходник под курсором / всегда исходник». В последних двух режимах кнопка не нужна.

### 3. `build_visual_rows`

Строка сеточной таблицы — всегда одна визуальная строка, без переноса:

```rust
let ranges = if grid_table_at(line_idx).is_some() || !(word_wrap && wrap_cols > 0) {
    vec![(0, line.chars().count())]
} else { wrap_line_ranges(line, wrap_cols) };
```

Высота в `VisualRowHeightIndex::from_rows`: шапка и тело — высота строки текста плюс вертикальные отступы ячейки, разделитель — линия 1–2 px.

### 4. Раскладка и рендер сетки

- Каждая ячейка рисуется через `row_painted_text` на подстроке `content`; все `line_chars` сдвигать на `content.start`, чтобы клик и курсор считались прежними средствами.
- Ширины колонок считаются один раз на таблицу: максимум по ячейкам, замеренный по shaped-тексту. Кэш по ключу `(first_line, хэш текста таблицы, style_rev)`; активная ячейка в ключ **не входит**, иначе Tab будет пересчитывать всю раскладку.
- `|` и разделитель в сетке не рисуются, вместо них линии сетки; разделитель — тонкая линия. Выравнивание колонок берётся из `aligns`.
- Маркеры (`**`, `` ` ``, ссылки) видны только в активной ячейке: вместо `is_active_line` использовать «курсор в этой ячейке».
- Рамки рисуются построчно, а не блоком, чтобы работала виртуализация.
- Hover-кнопки «+» у правого и нижнего края для добавления колонки и строки.

### 5. Курсор и ввод в режиме сетки

- Позиции курсора в пробелах у `|` притягивать к `content` (`col.clamp(c.content.start, c.content.end)`); сам `|` курсор не занимает.
- Перед каждой текстовой правкой в строке таблицы вызвать `guard_edit`; `Deny` — правка отменяется. Backspace в начале ячейки и Delete в её конце задевают `|`, поэтому ничего не стирают. Вставляемый текст пропускать через `sanitize_cell_input` (`|` → `\|`, переводы строк → `<br>`).
- Перехват клавиш до обычной обработки:
  - `Tab` / `Shift+Tab`: `tab(...)`. `AppendRow` добавляет строку и ставит курсор в первую ячейку новой строки. `Exit` на Shift+Tab в первой ячейке шапки — курсор на строку перед таблицей.
  - `Enter` / `Shift+Enter`: `enter(...)`, ячейка ниже или выше; в последней строке добавляется новая.
- Короткая строка (ячеек меньше, чем в шапке): перед переходом на недостающую ячейку нормализовать таблицу через `rewrite`, затем `nav_cursor`.
- Выделение через несколько ячеек: Delete очищает только содержимое; копирование через `to_tsv`, вставка TSV через `from_tsv`. Для этого понадобится функция «прямоугольник ячеек по двум позициям» — её в `table.rs` пока нет, добавить с тестами.

### 6. Структурные команды

Строка и колонка выше/ниже/удалить/переместить, выравнивание колонки, сортировка. Все через `TableModel` + `rewrite`, результат — одна транзакция undo (адаптер `LineEdit` → замена диапазона строк в буфере одним `replace`). Выставить их как команды для системы плагинов.

### 7. Выравнивание исходника

Пока курсор в таблице, ничего не перепаковывать. Вызывать `rewrite(..., pad = true)` при выходе курсора из таблицы или по команде. Ширину брать по `unicode-width` (CJK, эмодзи), а не `char_width`.

## Инварианты рендера сетки

Макеты на холсте нарисованы статичной HTML-вёрсткой с CSS-grid. В редакторе таблица рисуется построчно (одна визуальная строка на строку исходника), поэтому ниже то, что нужно соблюсти, чтобы результат выглядел как макеты.

### Линии и строки

- Вертикальные разделители колонок рисуются на каждой строке таблицы от `top_of(v_idx)` до `top_of(v_idx) + height_of(v_idx)` без вертикальных отступов, чтобы линии соседних строк смыкались в одну сплошную. Координаты линий и фонов округляются до физических пикселей (с учётом scale factor). Между строками таблицы нет промежутков: ни margin, ни gap, ни дробных высот.
- Строка-разделитель (`|---|`) сохраняет полную высоту строки (нужна для номера в гуттере и клика), но вертикальные разделители проходят и через неё. Сама горизонтальная линия рисуется тонкой (1–2 px) по середине строки, а не толстой заливкой.
- У строк таблицы высота больше высоты строки текста на 8–12 px (вертикальные отступы ячейки). Эти высоты заносятся в `VisualRowHeightIndex`, строка не должна выбиваться из индекса.
- Фон шапки заливает всю высоту строки шапки, скруглённые углы только у внешних углов таблицы.

### Ячейки

- Внутренние отступы ячейки 12–14 px слева и справа. Текст не касается разделителя.
- Содержимое ячейки клипуется по её прямоугольнику: длинный текст обрезается (с многоточием или просто обрезкой), плашка `code`, ссылка и подчёркивание не выходят за границы колонки.
- Выравнивание по `aligns` (`:--`, `:-:`, `--:`) применяется к тексту внутри колонки с учётом отступов.
- Число колонок таблицы равно `block.col_count()` (длина `aligns`, то есть число ячеек шапки по GFM), а не максимуму числа ячеек по строкам и не числу `|`. Лишние ячейки в телах строк при рендере отбрасываются, недостающие рисуются пустыми.

### Кнопки «+» и «Исходник»

Все кнопки поверх таблицы рисуются отдельным слоем оверлея и не участвуют в раскладке: они не создают строк в `VisualRowHeightIndex` и не меняют высоту документа.

- Порядок отрисовки: фон строк и подсветка текущей строки, выделение, текст, сетка, затем кнопки. Кнопка никогда не перекрывается подсветкой текущей строки. Hit-test кнопок выполняется раньше обычного hit-test текста.
- «Добавить колонку» (`+`): справа от таблицы, по вертикальному центру строки шапки, отступ от правого края 8–12 px.
- «Добавить строку» (`+`): привязана к **последней строке таблицы**, а не к следующей строке исходника. По вертикали по центру этой строки, по горизонтали у левого края таблицы. Для неё слева от таблицы остаётся поле 16–20 px между гуттером номеров и таблицей. Не рисовать её внутри пустой строки после таблицы.
- «Исходник» (`</>`): справа от таблицы на уровне шапки, не перекрывает «+» добавления колонки (сдвигается правее или ниже).
- Кнопки видны только пока курсор внутри таблицы или при наведении на неё. Если курсор на строке сразу после таблицы, кнопки скрыты.

### Проверка внешнего вида

Перед сдачей пройти по чек-листу на таблице из 3 колонок и 4 строк (шапка и 3 строки тела) с разным выравниванием, длинным текстом в первой колонке, `` `code` ``, `**bold**` и ссылкой, при масштабах 100% и 150%:
- нет разрывов в вертикальных линиях, включая строку-разделитель;
- линии одной толщины и на одном пикселе у всех строк;
- текст не касается линий и не выходит за ячейку;
- кнопка «+» снизу не занимает отдельную строку и не пересекается с подсветкой строки под таблицей;
- число колонок на экране равно числу заголовков в исходнике.

## Порядок работ

1. `TableIndex`: перенос быстрого конечного автомата строк (`is_row`, `is_separator`, `align_of`) из `aquilum-app` для нулевой стоимости открытия файла.
2. `build_visual_rows`, высоты, ленивая компоновка (`compute_table_layout` только для строк в `visible_range`).
3. Курсор и ввод в ячейке: притягивание к `content`, `guard_edit`, Tab/Enter, `AppendRow`.
4. Режим «исходник»: `raw_table`, `grid_table_at`, кнопка и `Ctrl+/`, сброс при выходе.
5. Активная ячейка с маркерами, hover-кнопки «+», структурные команды.
6. TSV, выделение по ячейкам, сортировка, команды для плагинов.

## Критерии приёмки

- Открытие и прокрутка документа со 100+ таблицами происходит мгновенно (< 10 мс), без зависания и без всплесков памяти.
- Набор текста в ячейке и Tab/Enter не меняют раскладку остальных таблиц и не вызывают пересчёта ширин колонок.
- Backspace/Delete на краю ячейки и любая правка строки-разделителя в режиме сетки ничего не меняют; введённый `|` превращается в `\|`.
- Таблица после `rewrite` снова корректно распознаётся автоматом, `TableModel::parse` даёт ту же модель (идемпотентность).
- Включение и выключение режима «исходник» не сдвигает прокрутку, курсор остаётся на том же символе; уход курсора из таблицы возвращает сетку.
- Одно структурное действие откатывается одним undo.
- Сетка соответствует разделу «Инварианты рендера»: сплошные линии без разрывов, отступы и клиппинг ячеек, кнопки в оверлее без собственных строк.
- `TableIndex` заполняется при первом `refresh`/`scan_rope`, даже если ревизия буфера равна 0 (хранить `rev: Option<u64>`).
- Курсор и выделение работают для кириллицы, эмодзи и широких символов (индексы chars, не байты).
- Новые тесты на всё добавленное; существующие тесты `markdown.rs` и `markdown_doc.rs` проходят.

## Известные риски и решения

- **Риск деградации скорости от `pulldown_cmark`**: решён переходом на быстрый синтаксический сканер строк по схеме `aquilum-app`.
- **Кодовые блоки**: разделители `|` внутри кодовых блоков (```` ``` ````) не должны приниматься за таблицы; сканер проверяет состояние блока через `CodeScanState`.
- `apply_edit` в `markdown_doc.rs` каждый раз перепарсивает документ и выдаёт новые `BlockId`/`NodeId`; если живой путь блочный, кэш ширин ключевать по `first_line`, а не по `block_id`.
- `render_live_styled_row` и `row_painted_text` должны оставаться синхронными, в том числе для ячеек.
