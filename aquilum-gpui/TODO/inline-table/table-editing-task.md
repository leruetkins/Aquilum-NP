# Задание: инлайн-редактирование таблиц в живом просмотре markdown (GPUI)

## Цель

Таблицы GFM в редакторе рисуются сеткой, а редактируются прямо в ней. Буфер остаётся единственным источником правды: сетка только показывает текст, курсор и выделение живут в символах исходной строки. Отдельных мини-редакторов на ячейку нет.

Дополнительно: у каждой таблицы есть переключатель «исходник», который на время показывает её обычным текстом с `|` и разделителем.

## Контекст и файлы

- `markdown.rs` — живой путь: построчная модель (`classify_line`, `build_visual_rows`, `VisualRowHeightIndex`, `row_painted_text`, `PaintedRow.line_chars`). Все колонки — индексы символов (chars) внутри строки.
- `markdown_doc.rs` — блочная модель на `pulldown_cmark` (`ENABLE_TABLES` включён). Какой путь реально рисует, уточнить в коде; задание рассчитано на построчный.
- `views/app_view.rs` — рендер строки (`render_live_styled_row` должен совпадать с `row_painted_text`) и обработка клавиш.
- `table.rs` (приложен, 18 тестов проходят, `pulldown-cmark 0.13`) — чистая модель таблицы без UI и состояния. Не переписывать, расширять только по необходимости и с тестами.

### API `table.rs`

- Блоки: `find_tables(lines) -> Vec<TableBlock>`, `table_at(lines, line)` (парсит только абзац вокруг строки; не знает про кодовые блоки, результат фильтровать по `analyze_code_blocks`). `TableBlock { first_line, last_line, aligns }`, `row_of_line`, `line_of_row`, `sep_line`, `contains`. Таблицы внутри цитат и списков не находятся.
- Ячейки: `split_row(line) -> Vec<Cell { outer, content }>` в char-индексах, `\|` не разделитель; `cell_index_at(cells, col)`.
- Модель: `TableModel::parse / serialize(pad, width) / insert_row / delete_row / insert_col / delete_col / move_col / set_align / sort_by_col / from_tsv / to_tsv`.
- Правки: `LineEdit { first_line, old_line_count, new_lines }`, `rewrite(block, model, pad, width)`.
- Клавиши: `tab(...) / enter(...) -> Option<Nav { To, AppendRow, Exit }>`, `nav_cursor(block, lines, row, cell, Place)`.
- Защита: `guard_edit(block, line_idx, line, sel) -> EditGuard { Allow, Deny }`, `sanitize_cell_input`.

## Что сделать

### 1. Индекс таблиц

```rust
pub struct TableIndex { rev: u64, blocks: Vec<TableBlock> }
impl TableIndex {
    pub fn refresh(&mut self, rev: u64, lines: &[&str]) { if self.rev != rev { self.blocks = find_tables(lines); self.rev = rev; } }
    pub fn at(&self, line: usize) -> Option<&TableBlock> {
        let i = self.blocks.partition_point(|t| t.last_line < line);
        self.blocks.get(i).filter(|t| t.first_line <= line)
    }
}
```
Обновлять по ревизии буфера. Для больших документов перейти на `table_at` вокруг изменённой строки.

### 2. Режим «исходник» (переключатель на одну таблицу)

Состояние редактора: `raw_table: bool`. Единственная точка принятия решения:

```rust
fn grid_table_at(&self, line: usize) -> Option<&TableBlock> {
    let t = self.tables.at(line)?;
    if self.raw_table && t.contains(self.cursor_line) { None } else { Some(t) }
}
```

Везде, где нужен ответ «рисовать ли эту строку сеткой» (`build_visual_rows`, раскладка, Tab/Enter, `guard_edit`), использовать `grid_table_at`, а не `tables.at`.

Поведение:
- Включение: кнопка `</>` над правым краем таблицы или `Ctrl+/`. Тем же способом выключается. Курсор остаётся на том же символе.
- Пока режим включён и курсор в таблице: строки таблицы рисуются как обычный текст (видны `|` и `|---|`), перенос по словам снова работает, Tab и Enter обычные, `guard_edit` не применяется, правки свободные.
- Выход курсора из таблицы (`tables.at(cursor_line).is_none()` или курсор вне блока) сбрасывает `raw_table = false`, таблица снова сеткой.
- Сломанная правкой таблица перестаёт находиться `find_tables` и остаётся текстом, режим тоже сбрасывается.
- После переключения пересчитать высоты строк таблицы в `VisualRowHeightIndex`, иначе прокрутка сдвинется.

Кнопка (макеты 4 и 5 на холсте):
- Квадрат 28×28, скругление 6 px, подпись-глиф `</>` моноширинным шрифтом. Видна только когда курсор в таблице или при наведении на таблицу.
- Состояния: обычная (рамка нейтральная, фон `#2a2d35`), нажатая (рамка и глиф акцентные `#7aa2ff`, фон акцента 20%, `aria-pressed = true`), наведение с подсказкой «Исходник таблицы Ctrl+/».
- Положение: над правым краем таблицы, вне её рамки, не перекрывает кнопки «+» у краёв.
- Опционально: настройка «Таблицы: всегда сетка / сетка, но исходник под курсором / всегда исходник». В последних двух режимах кнопка не нужна.

### 3. `build_visual_rows`

Строка сеточной таблицы — всегда одна визуальная строка, без переноса:

```rust
let ranges = if grid_table_at(line_idx).is_some() || !(word_wrap && wrap_cols > 0) {
    vec![(0, line.chars().count())]
} else { wrap_line_ranges(line, wrap_cols) };
```

Высота в `VisualRowHeightIndex::from_rows`: шапка и тело — высота строки текста плюс вертикальные отступы ячейки, разделитель — линия 1–2 px.

### 4. Раскладка и рендер сетки

- Каждая ячейка рисуется через `row_painted_text` на подстроке `content`; все `line_chars` сдвигать на `content.start`, чтобы клик и курсор считались прежними средствами.
- Ширины колонок считаются один раз на таблицу: максимум по ячейкам, замеренный по shaped-тексту. Кэш по ключу `(first_line, хэш текста таблицы, style_rev)`; активная ячейка в ключ **не входит**, иначе Tab будет пересчитывать всю раскладку.
- `|` и разделитель в сетке не рисуются, вместо них линии сетки; разделитель — тонкая линия. Выравнивание колонок берётся из `aligns`.
- Маркеры (`**`, `` ` ``, ссылки) видны только в активной ячейке: вместо `is_active_line` использовать «курсор в этой ячейке».
- Рамки рисуются построчно, а не блоком, чтобы работала виртуализация.
- Hover-кнопки «+» у правого и нижнего края для добавления колонки и строки.

### 5. Курсор и ввод в режиме сетки

- Позиции курсора в пробелах у `|` притягивать к `content` (`col.clamp(c.content.start, c.content.end)`); сам `|` курсор не занимает.
- Перед каждой текстовой правкой в строке таблицы вызвать `guard_edit`; `Deny` — правка отменяется. Backspace в начале ячейки и Delete в её конце задевают `|`, поэтому ничего не стирают. Вставляемый текст пропускать через `sanitize_cell_input` (`|` → `\|`, переводы строк → `<br>`).
- Перехват клавиш до обычной обработки:
  - `Tab` / `Shift+Tab`: `tab(...)`. `AppendRow` добавляет строку и ставит курсор в первую ячейку новой строки. `Exit` на Shift+Tab в первой ячейке шапки — курсор на строку перед таблицей.
  - `Enter` / `Shift+Enter`: `enter(...)`, ячейка ниже или выше; в последней строке добавляется новая.
- Короткая строка (ячеек меньше, чем в шапке): перед переходом на недостающую ячейку нормализовать таблицу через `rewrite`, затем `nav_cursor`.
- Выделение через несколько ячеек: Delete очищает только содержимое; копирование через `to_tsv`, вставка TSV через `from_tsv`. Для этого понадобится функция «прямоугольник ячеек по двум позициям» — её в `table.rs` пока нет, добавить с тестами.

### 6. Структурные команды

Строка и колонка выше/ниже/удалить/переместить, выравнивание колонки, сортировка. Все через `TableModel` + `rewrite`, результат — одна транзакция undo (адаптер `LineEdit` → замена диапазона строк в буфере одним `replace`). Выставить их как команды для системы плагинов.

### 7. Выравнивание исходника

Пока курсор в таблице, ничего не перепаковывать. Вызывать `rewrite(..., pad = true)` при выходе курсора из таблицы или по команде. Ширину брать по `unicode-width` (CJK, эмодзи), а не `char_width`.

## Порядок работ

1. `TableIndex`, `build_visual_rows`, высоты, рендер сеткой только для чтения.
2. Курсор и ввод в ячейке: притягивание к `content`, `guard_edit`, Tab/Enter, `AppendRow`.
3. Режим «исходник»: `raw_table`, `grid_table_at`, кнопка и `Ctrl+/`, сброс при выходе.
4. Активная ячейка с маркерами, hover-кнопки «+», структурные команды.
5. TSV, выделение по ячейкам, сортировка, команды для плагинов.

## Критерии приёмки

- Набор текста в ячейке и Tab/Enter не меняют раскладку остальных таблиц и не вызывают пересчёта ширин колонок.
- Backspace/Delete на краю ячейки и любая правка строки-разделителя в режиме сетки ничего не меняют; введённый `|` превращается в `\|`.
- Таблица после `rewrite` снова находится `find_tables`, `TableModel::parse` даёт ту же модель (идемпотентность).
- Включение и выключение режима «исходник» не сдвигает прокрутку, курсор остаётся на том же символе; уход курсора из таблицы возвращает сетку.
- Одно структурное действие откатывается одним undo.
- Курсор и выделение работают для кириллицы, эмодзи и широких символов (индексы chars, не байты).
- Новые тесты на всё добавленное; существующие тесты `markdown.rs` и `markdown_doc.rs` проходят.

## Известные риски

- Не проверено, как `pulldown_cmark` трактует строку без `|` сразу после таблицы (по GFM она может стать строкой таблицы, тогда `last_line` расширится). Проверить на реальном корпусе заметок и покрыть тестом.
- `table_at` не знает про кодовые блоки; фильтровать результат по `analyze_code_blocks`.
- `apply_edit` в `markdown_doc.rs` каждый раз перепарсивает документ и выдаёт новые `BlockId`/`NodeId`; если живой путь блочный, кэш ширин ключевать по `first_line`, а не по `block_id`.
- `render_live_styled_row` и `row_painted_text` должны оставаться синхронными, в том числе для ячеек.
