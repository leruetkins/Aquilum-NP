# План: инпут-латентность редактора (Delete, удержание клавиши, сплиты)

Симптомы (подтверждены чтением кода):

1. Первый Backspace/Delete после открытия большой заметки «задумывается» ~2 с (в debug),
   дальнейшие удаления мгновенные.
2. Удержание буквы: 13–15% GPU и ~5% CPU (≈40% одного ядра на 8 ядер) — и это без word wrap,
   так что пересчёт переносов ни при чём.
3. Одна и та же заметка в двух панелях сплита умножает стоимость правки на число панелей.

«Мультиокна» в смысле отдельных OS-окон нет: один `open_window` (`src/main.rs:61`),
«Move to new window» — заглушка, пишет только статус (`src/views/tab_context_menu.rs:529-538`).
Речь о сплитах внутри одного окна.

## Причины (проверено по коду)

| # | Причина | Место |
| :- | :--- | :--- |
| 1 | Backspace/Delete вызывает `doc.ensure_table_index()` **до** проверки выделения; у заметки >3000 строк индекс после открытия не полный (`fully_scanned=false`, `table.rs:155,248`), поэтому первый вызов = полный `scan_rope` по всему документу. Повторные — мгновенны. То же в Ctrl+C | `views/app_view.rs:4427`, `:3973`; `document_buffer.rs:165-172` |
| 2 | После быстрого инкрементального `update_window_line_after_edit` безусловно ставится `visual_cache_dirty = true` → на каждый символ полный ребилд окна `2*MARGIN_LINES+1 = 6001` строк | `workspace/view_state.rs:536,534,901-917`; `editor_window.rs:35,327` |
| 3 | На каждый символ `update_window_line_after_edit` пересканирует весь диапазон окна таблиц (`ensure_table_index_for_window` по `[start_line, end_line]`); после `apply_edit` покрыт только абзац → перескан ~6200 строк. Второй такой вызов — в обработчике клавиш | `workspace/view_state.rs:547`; `views/app_view.rs:4133` |
| 4 | Settle-кадры усадки layout запрашиваются при каждом изменении scroll-инпутов, а высота меняется с каждым символом → непрерывный репейнт при key-repeat | `views/app_view.rs:8506-8515`; выставление счётчика `:986, :4989, :5068, :5095` |
| 5 | Undo-склейка Backspace — prepend: `insert_str(0, …)` сдвигает весь накопленный буфер, серия из n Backspace = O(n²) копирования. Forward delete уже `push_str` (амортизированный O(1)). Склейка рвётся на `\n` (`:690`), так что деградация — на длинных строках и при стирании мегабайтов одной серией | `document_buffer.rs:688-706` |
| 6 | Внешние view (сплит с той же заметкой): правка внутри их окна сбрасывает окно целиком (`EditorWindow::default()` + dirty) → полный ребилд в `ensure_inactive_views_built` на следующем кадре. Правки вне окна — только сдвиг above/below, это уже дёшево | `workspace/view_state.rs:1032-1057`; `views/app_view.rs:4796-4882` |

Вторично: `poll_fs_changes` каждые 150 мс делает `path.exists()` для каждой открытой заметки
на UI-потоке — двухсекундный фриз не объясняет, но микрофризы добавлять может, особенно на
сетевых дисках (`src/main.rs:141,145`; `src/state.rs:1619`).

## Шаги

1. **Delete/Backspace без полного скана.** В обработчике сначала `selection_range`; индекс
   таблиц запрашивать только при наличии выделения и через
   `ensure_table_index_for_window(start_line, end_line)`. То же для Ctrl+C (`app_view.rs:3973`).
2. **Не грязить весь кеш после успешного инкрементального апдейта** (`view_state.rs:536`).
   Инвалидация обязана остаться там, где правка меняет kind строки (текст↔заголовок/таблица)
   или число строк; в остальных случаях — пересборка одной строки.
3. **Точечное расширение `covered_range`** таблиц вместо перескана всего окна на каждый символ
   (`view_state.rs:547`, `app_view.rs:4133`).
4. **Settle-кадры** — на resize/scroll/смену ширины, а не на каждую текстовую правку.
5. **Undo Backspace без O(n²)**: хранить удалённые фрагменты в векторе (или отдельные
   `TextChange` в одном undo-step) вместо prepend в одну строку.
   *Отпадает при внедрении посимвольного undo/redo (AkelPad `AECO_DETAILEDUNDO`): коалесценция
   удаляется целиком — prepend исчезает по построению.*
6. **Сплиты:** для внешней view той же заметки — инкрементальный апдейт одной строки при правке
   внутри её окна на той же строке; сдвиг above/below вне окна (уже так); полный ребилд — только
   при изменении числа строк.

## Ожидаемый результат

- Удержание буквы: одна вставка в rope + инкрементальный `apply_edit` (абзац) + апдейт одной
  строки + один репейнт; без полных проходов по документу и по окну.
- Backspace/Delete: без фриза на первом удалении; стирание мегабайтов одной серией — O(n)
  (после п.5).
- Сплиты: одна заметка в N панелях — один инкрементальный апдейт + N дешёвых (после п.6).

Замерять в release: debug-сборка в разы медленнее и часть фризов даёт сама.

## Риски / инварианты

- П.2 не должен сломать инвалидацию при смене markdown-kind строки и при раскрытии/скрытии
  таблиц — там `visual_cache_dirty` легитимен (`view_state.rs:883,896`).
- П.1 не должен сломать определение «удаление внутри таблицы»: без полного индекса
  `tables.at(line)` вне окна вернёт None — скан должен покрывать диапазон выделения.
- Настоящее второе окно (если появится): с общим `AppState` упирается в п.6, с независимыми
  буферами — в конфликты сохранения (сейчас разные окна связаны только опросом ФС раз в 150 мс).
